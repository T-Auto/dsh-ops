# 编辑、代码导航与审阅：当前设计决策

[English](design-decisions-20261102.md)

日期：2026-11-02；基线：`main@065cd7f`。本轮对
[#424](https://github.com/T-Auto/dsh-ops/issues/424)、
[#459](https://github.com/T-Auto/dsh-ops/issues/459)、
[#534](https://github.com/T-Auto/dsh-ops/issues/534) 的结论是：**暂不增加新的生产功能**。

## #424：revision 绑定的区间与 anchor

从带行号、可能分页或截断的结果重新拼接唯一旧文本，确实不方便。但行号不等于文件身份、
字节边界或完整读取凭据。保留现有 expectedRevision、唯一旧文本匹配与单文件原子发布契约。

| 候选 | 收益 | 新增责任 | 当前决定 |
| --- | --- | --- | --- |
| PTC 行对象 helper | 减少重复转换代码 | 连续完整输入、换行/BOM 精确重建、旧文本唯一性 | 最适合后续小实验，当前不发布 helper |
| revision + 行/字节范围 | 避免文本定位歧义 | 首尾开闭、编码边界、空插入、重叠与锁内重验 | 契约和负向用例确定前不做 |
| 不透明读取 token | 绑定具体读取 | 会话生命周期、权限撤销、缓存淘汰、身份及重放 | 没有量化收益，不增加状态 |
| hashline/文本锚点 | 文本引用紧凑 | 冲突、重复行、过期身份、归一化 | 不做模糊定位或自动 rebase |

当前安全路径是 PTC 直接使用 typed read 数据及其 revision，检查状态与完整性，再携带
expectedRevision 和精确旧文本编辑。歧义或截断时先补足新鲜上下文。
[PR #541](https://github.com/T-Auto/dsh-ops/pull/541) 的真实 read→edit 回归和外部改写拒绝
属于现有契约修复，不是新的 range API。

将来 helper 至少必须验证：

- 重复行/重复区域拒绝歧义，无字节变化；相邻编辑定义顺序，重叠拒绝，单文件全有或全无。
- CRLF、BOM、UTF-8 多字节、末尾无换行：范围外字节完全保留。
- 分页、截断、缺失行：拒绝不完整凭据，不重建未见字节。
- 读取后任意位置被外部修改：revision 冲突，不静默搬移范围。
- symlink/reparse、文件身份变化、只读与权限范围外：仍由现有边界拒绝。
- 成功：返回新 revision 和准确的效果回执。

重新评估需要独立实现的原型、上述真实负向断言，以及代表性任务的失败/重试次数、
输入输出字节对照。不复制其他项目源码或 lineage 内部结构；本决策不宣称已完成原型或收益验证。

## #459：Tree-sitter 符号地图

导航时 outline 可以少返回文本，但当前材料尚不能证明一个小型、可跨平台维护、遵守 OPS
权限边界且端到端有收益的实现。本轮继续使用定向搜索与范围读取，不添加解析器依赖或第二条文件执行路径。

核验候选为已关闭未合并的 [PR #469](https://github.com/T-Auto/dsh-ops/pull/469)，
head `badd4c8`。相对基线的 `src/` diff 在 19 个文件增加 2,522 行，不含测试和文档。
其[基准说明](https://github.com/yanfei0725/dsh-ops/blob/badd4c83ae04bfe85555aed08f6915e534832b07/docs/symbol-map-benchmark.md)
报告一个生成的 400 行 TypeScript 文件：首次解析 14.7 ms，缓存命中 0.13 ms；outline
1,282 B，对照默认部分读取 5,039 B。这是贡献者的测量，不是本轮新的跨平台基准。

缓存读数不能替代“定位符号→读取代码→完成任务”的总成本，也未覆盖总 RSS、语法加载、
失效及连续读取许多不同文件。小 outline 与所需代码正文不是等量工作；估算 token 不是模型 usage 或账单。

Queries 在已经解析的语法树上匹配节点，并不免除解析和树存储。Tree-sitter 的字节/行列
坐标、ERROR/MISSING 节点都需要明确处理。参见官方
[解析文档](https://tree-sitter.github.io/tree-sitter/using-parsers/2-basic-parsing.html)及
[Query 语法](https://tree-sitter.github.io/tree-sitter/using-parsers/queries/1-syntax.html)。

重新评估需要：

- 唯一的文件权限路径，保留 no-follow、凭据、revision、取消；outline 不算完整读取，不授权后续编辑。
- 文件大小、解析时间、parser/tree/cache 内存及语法数量的明确上限；支持平台上的冷/热/churn/多文件测量。
- 固定 grammar 版本、明确缺失语言错误，不靠安装脚本，也不在缺 grammar 时假成功返回空 outline。
- 过期 revision、语法错误、Unicode/换行位置、会话/权限变化、路径替换、缓存淘汰的负向回归。
- 包含后续代码读取、全部声明和输出字节、正确性的任务对照；报告中位数与波动，不把时间阈值写进 CI。
- 符合贡献规模约束的独立小切片。

保留贡献者分支；不合并、不改写、不删除该候选。

## #534：验证环境、合并队列与 schema probe

继续以现有 CLI 审阅快照作为产品入口。fork CI 关联及 GitHub merge-state 缺陷由
[PR #538](https://github.com/T-Auto/dsh-ops/pull/538) 单独修复。快照是证据，不是合并批准。

本轮不新增自动环境构建器、merge-train 执行器或模型可见审阅组件。这些功能要负责候选
代码构建、依赖安装、取消、清理和跨 PR 状态，目前尚无约定工作负载证明新增产品面的收益。

[现有命令](审阅快照.md) 一次最多五个 PR，JSON 上限 64 KiB。本轮一次真实三 PR 观察输出
8,876 个 UTF-8 字节；请求基线与 PR 报告基线不同时，且未提供本地探测，正确返回 partial。
这是单次命令的输出大小，不是与人工审阅相比的节省；没有常驻模型 schema。
未进行受控的人工/自动审阅成本比较，不声称节省了多少 token 或时间。

| 提案 | 当前路径 | 新实现需要的证据 |
| --- | --- | --- |
| P1 隔离验证 | 显式独立 worktree/依赖图，记录 base/head、命令、失败、跳过 | 可复现基线/候选工作负载、有界日志、取消清理、不改维护者 checkout、明确环境和凭据策略 |
| P2 merge train | 只读快照/隔离合并探测；必要时显式审阅集成分支 | base/head 失效、顺序依赖图、组合树的冲突与测试；远端变更仍是独立显式操作 |
| P3 schema/模型工具 | 离线比较现有 catalog 与声明 | 重复出现的审阅任务、schema/context 成本、按需加载、有界输出，不为偶发工作增加常驻工具 |

重新开启时一次选一个可独立审阅的交付物和测量协议。构建失败、缺 worker、缺 CI、策略阻塞、
未知合并证据均必须显式保留，不得自动重试后把它们写成成功。

## 成本口径与本次验证

基线 catalog 的紧凑 `JSON.stringify({description, parameters})` UTF-8 字节：
edit_file 1,514；read_files 660；inspect_local_file 814。不含输出 schema、工具名、宿主封装或
提示词，属于 catalog 片段测量，不是完整请求或 token 数。本次文档不改变 schema、声明或默认值，产品 schema 增量为零。

本切片只验证文档/链接一致性和生产源码未变。既有测试只证明它们真实断言的行为，不能用来
宣称未实现的 range editor、parser 或审阅自动化已通过未来验收矩阵。
