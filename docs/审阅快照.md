# 审阅快照 CLI

English: [Review snapshot](review-snapshot.md).

通过一个显式命令收集 #356 的 P0 审阅证据。这个独立集成不增加常驻工具或
file/PTC schema。需要已登录 github.com 的 `gh`；可选本地合并预演还需要 Git。

```console
dsh-ops review snapshot --repo T-Auto/dsh-ops --prs 389,392 --base main --workflow ci.yml --checkout .
```

已构建的源码检出使用 `node bin/dsh-ops.mjs review snapshot ...`。
`--repo`、`--prs` 必填；每次接受 1–5 个不同的正整数 PR 号。`--base` 默认 `main`，
`--workflow` 默认 `ci.yml`，也接受其他 workflow 文件名或数字 ID。
省略 `--checkout` 则只收集 GitHub 证据。命令不会安装/登录 `gh` 或修改 profile。

JSON 包含：

- PR 作者、状态、Draft/review 状态、规模、准确 head/base SHA、fork 仓库与维护者修改权限。
- 最多 25 个变更路径，以及依赖/workflow/schema/changelog 风险提示。这些是审阅线索，
  不代表发现了缺陷；不完整的文件窗口会明确标记。
- 最多三个 closing issue、assignees，以及最后十条评论中的可能认领证据。
  匹配项保留作者、摘录和 URL，不证明归属；不会收集全部 timeline cross-reference。
- 同时匹配 head SHA、PR 号和 `pull_request` 事件的最新运行，包含 event、attempt、URL
  和最多 50 个 job 结论。不会拿 push 或手动运行替代 PR 验证。
- 当前指定 base 的 SHA 与**同一个 workflow** 的最新匹配 push 运行，分开呈现 base 与
  PR 证据。这不是其他 workflow、required check 或分支保护的聚合健康结论。
- 对该次捕获 base SHA 的本地合并预演：`clean`、带路径的 `conflicts`，或带原因的
  `unknown`。它只是当时的预演，不是合并批准。

## 边界与未知结果

每次调用重新读取；只有同一次调用里的相同读取共享结果。head 改变后不会沿用旧绿灯。
运行查找最多检查 20 条 API 结果。缺少凭据、无匹配运行、响应无效、本地 commit 对象
不存在、进程失败和超时都会保留为未知证据。有限的文件/issue/评论/job 窗口不会冒充
完整清单。

单个子进程限时 20 秒、收集上限 512 KiB，整个调用使用 120 秒截止信号。JSON 上限
64 KiB；超过时保留 PR 标识与 URL、设置 `outputTruncated`，提示减少 PR 数量。
退出 0 表示请求的有界快照已组装且所需证据无缺失；退出 1 表示部分证据或输入无效/
不可用，应检查 JSON。完整快照也可以记录红色 CI；任何退出码都不是安全合并认证。

## 本地合并隔离

`--checkout` 指向已具有所需 commit 对象的本地仓库。不会在其中 fetch、检出分支、
更新分支、push 或执行 merge。预演建立临时 bare 仓库，使用空 template，忽略全局/
系统 Git 配置和继承的 Git 命令覆盖，仅以 alternate 读取源对象库；不会复制源仓库
hooks 或配置的 merge driver。新增合并对象只写入临时库，随后删除该临时目录。
对象缺失时返回 unknown，不自动下载。

本次仅实现 #356 后续讨论中的 CLI-first P0 证据快照。审阅环境搭建、基线测试、
自动认领、CI 等待/日志分析、合并列车、schema probe 和可选 review 工具组件属于
后续切片。本命令不自动作出审阅决定或修改 GitHub。
