# 动态工具目录

English: [Dynamic tool directory](dynamic-tool-directory.md)。

## Native 渐进发现

Discovery controller 为每个 agent 提供一个由 OPS 自己拥有、按作用域计算的提示词段，只保留一行指向当前真实可见的 `ops_discover_tools`，不再常驻未加载能力目录。查询结果中的内置名称、搜索词和契约来自现有 capability catalog；第三方条目来自现有 Native provider。这里没有第二套工具注册表。Standard 与 Cordis 初始只发布 `ops_inspect_local_file`、`ops_glob`、`ops_grep`；`ops_read_files` 与 `ops_result` 需要时通过发现加载。

- **Callable（可调用）**表示当前 agent 已经看得到工具 schema。任务已有 resident/callable 工具覆盖时，优先使用它，不要重复加载。
- **Discoverable（可发现）**只表示有资格被选择，不表示已 callable，也不表示执行已授权。用任务关键词查询 `ops_discover_tools`，或用 `{"query":"select:ops_read_pdf"}` 精确选择内置工具，用 `{"query":"select:acme_lookup"}` 精确选择 provider 工具。
- 选择不执行工具动作。新选择的工具在**下一个 model step**才出现；必须等 schema 出现后再调用。参数和默认值以 schema 为准，不以目录提示为准。
- 无匹配只覆盖当前 eligible pool。不要原样重复查询、猜测工具/格式，或通过其它执行器绕过权限拒绝。

查询搜索完整 eligible pool，按需返回有界结果；提示词不再每次列出最多 20 个未加载条目。提示是数据，不是权限或指令。不会覆盖 provider 自己的提示词段，字面量花括号也不会被 OPS 插值。

eligible pool 会排除不允许的内置工具、当前 mode 已 resident 的工具、read-only 下会修改数据的内置工具、非 active/未安装 provider、不在 operator allowed 列表中的 provider、disabled provider，以及对当前 agent 不可用或隐藏的 provider。loader 不可见、guidance 关闭、ownership 撤销或 assembly 为 PTC-only 时，不输出 Native 目录。卸载只移除本 controller 的工具和文本。

目录渲染只读取 pool，不启动 worker，也不递归 assembly；它不是 process probe。既有 presentation 检查仍在生命周期和执行边界运行。

## 可见性不是授权

`registerNativeCapability()` 接受向后兼容的可选 hook：

```ts
discoverable?(agent: Agent): boolean
```

该同步 hook 必须无副作用，并且只有返回严格的布尔值 `true` 才显示条目。返回 `false`、`undefined`、`null`、`0`、对象、Promise（包括最终解析为 `true` 或 `false`）或抛错都隐藏条目。误返回的 Promise 若拒绝，OPS 会消费其拒绝并继续 fail closed；不支持异步 eligibility。`available(agent)` 表示 provider 是否 ready，`discoverable(agent)` 表示目录/搜索是否可见。省略 hook 则保持原有基于 readiness 的发现行为。需要按 agent 隐藏条目时，provider 必须依据自己的权威状态实现此检查；OPS 不会从 description 推断执行权限。改变可见性本身不会撤销执行授权。

两个 hook 在查询时都会重新读取，不缓存 discovery permission。provider 变化必须通过既有 disposer 和重新注册生命周期通知 controller 并使 publication 失效；reload 会得到新的 selection token。仅限执行的 `authorize(exec)` **永远不会用于构建或搜索目录**，每次 provider 动作即将执行前仍用真实 execution context 重新检查。目录出现不授予权限；provider 即使已加载，也必须在 `authorize` 中执行撤销检查。

## Native 与 PTC 是不同投影

`src/discovery/catalog.ts` 导出纯函数 `nativeCatalog()` 和 `NativeCatalogEntry` 类型；`src/discovery/prompt.ts` 导出 `renderNativeDirectory()`。输入必须是已过滤的 Native candidate，函数不注册工具、不授权。这些不是 PTC SDK API。

第三方 Native provider 不得被广告成 SDK 函数。PTC-only agent 使用真实的 `ops_load_sdk` 契约和 typed API，不使用 `ops_discover_tools`；此时 Native 目录会被抑制。PTC 同样只保留一行加载器指引。加载器描述列出配置的原始名称（包括按需加载的 `result`），独立于 Native provider；选择与提交时重新检查当前权限，不把配置名单视为授权。

## ops-ptc 的渐进式披露开关

PTC 呈现下本来就不发布 Native 的 `ops_discover_tools`：这是设计而不是故障，PTC-only 会话只通过
`ops_load_sdk` 加载类型化 API，Native 目录会被抑制。因此 `ops-ptc` 模式只有 SDK loader 这一条渐进式披露
入口：`ops-ptc.dynamicTools` 与 bundle 级 `global.dynamicTools` 同时开启时才发布 `ops_load_sdk`
（两者是与门；插件页把 bundle 开关渲染为总闸）。完整配置见[配置参考](配置参考.md)的 OPS PTC 模式节。

- 关闭 `dynamicTools` 后不再发布 `ops_load_sdk`，也就没有新加载按需 API 的入口；常驻与显式发布的 API 不受影响
  （`ops_inspect_local_file` 以及配置为 `alwaysLoaded` 的 API 继续可见），本会话已加载的 API 仍可调用。
- `result` 是加载器的隐式选择例外（`allowedTools: []` 时仍可加载），但没有加载器就没有加载入口。若要求关闭
  渐进式披露后仍能使用结果引用，把它放进该分区的 `alwaysLoaded: [result]`。
- **加载的 API 下一轮才可见。** `ops_load_sdk` 只把名称排队；当前轮次冻结的 SDK 快照里没有它们，必须等所属
  会话提交 `step/end`、下一个模型步骤重新组装后才出现。不要在同一个 `run_code` 里调用刚加载的 API
  （它一定失败）；先 `return`，下一轮再调用。系统提示组装、诊断组装与工具注册通知都不会提前激活排队请求。
- 该开关不影响 `standard`/`cordis` 的 Native 发现：`discovery.enabled` 与各模式的 `dynamicTools` 是独立的
  发布选择，PTC 呈现也不会把 Native 目录带回来。

## 聚焦验证

```console
npm run build
node test/run.mjs discovery-catalog
```

测试使用真实 Cordis scope、system-prompt assembly 和工具 dispatch，不执行 native worker；覆盖加载前的加载器指引、next-step activation、无匹配、provider 可见性/ready、权限降级、执行授权/撤销、两个 agent、reload、PTC-only 抑制、取消、卸载和重复 assembly 稳定性。Native execution 与完整跨平台 release gate 仍由其它检查负责。
