# 内部常驻任务队列

[English](resident-task-queues.md)

这个 #872 切片向现有宿主所属内核添加 Windows 内部 `task-v1` 协议，执行独立拥有的
fresh 任务。它不发布工具，也不切换生产 fresh/Jobs 适配器。POSIX 尚未证明等价的
公开宿主所有权，因此不声明 task capability。

宿主发送 `task.execute`：唯一 `requestId`、精确私有 `ownerKey`、
`lifetime: foreground | job`、有限正数 `graceMs`、可选 `timeoutMs`，以及
`output: { memoryBytes: 64000, spillBytes: 67108864 }`。小数毫秒保持现有 fresh
计时语义。timeout 是包含排队时间的独立硬执行上限，提升为 job 后仍然有效。
Jobs 宿主适配器必须自行管理观测/移交计时；希望超时后继续运行的工作不能携带此硬上限。
本切片校验 spill 预算，但尚未实现可恢复 spill，目前只保留输出尾部。

八个固定 worker 消费 FIFO 队列。最多保留 32 个任务记录、32 个 owner 和 64 个
待完成 owner 控制请求。终态记录在 `task.release` 前继续占用槽位。deadline waiter
受任务记录数限制，并在 teardown 时 join。同一 owner 的 fresh 任务可并行执行；
持久 shell 命令继续使用独立的每会话 FIFO。

每次队首通过 `task.admit` 向宿主请求当前权限。宿主返回 `task.admission`，包含
`decision: launch` 和公开 sandbox 约束后的精确 `launch: { argv, cwd, env }`，
或者 `decision: reject` 与结构化错误。内核不解析权限，也不复用批准。准入等待期间，
取消和 owner 关闭可以结算尚未开始的任务；迟到回复不能恢复已完成任务。拒绝时不启动子进程。

每次启动使用公开宿主所拥有内核范围内的独立嵌套 Windows Job。共享进程基础层提供
关闭管道的 stdin、原始输出捕获和持有的根进程句柄。`task.started` 确认成功创建进程，
并非产生效果之前的屏障。一旦尝试启动，丢失回执不能成为返回 `effectState: none` 的依据。

普通 foreground 根进程退出后，在配置 grace 内排空输出，然后终止剩余后代。
`lifetime: job` 显式保留根进程退出后的后代。`task.promote` 将同一个运行中范围变为
此生命周期，并返回 `task.promoted { accepted }`；同一把锁裁决提升与进入根退出回收。
正在回收或已完成的任务不能提升；单独创建宿主 job 记录不会改变原生所有权。提升不会复制
或重新启动任务。

现有 `cancel { requestId }` 仅作用于该范围。有界的所属 console signal 尝试之后进行
硬终止确认。完成需要 Job 为空、持有的根进程句柄已退出以及两个输出 reader 已 join。
`task.completed` 包含状态、实际退出码、效果状态、回收确认、流总字节数及结构化错误。
退出码 259 是有效值。捕获错误保留部分输出并报告 `OUTPUT_INCOMPLETE`，不能冒充成功 EOF。

`task.read` 指定流、原始字节 offset 和 `maxBytes`（1–65536）。`task.output`
回显请求 offset，返回 `retainedOffset`、`nextOffset`、`bytesBase64`、`lossy`、
`eof` 和错误。每个流保留最新 64,000 字节，并统计所有观测字节。更小读取上限返回最新
后缀并明确报告跳过部分。reader 不消耗彼此的游标。实时空输出不是 EOF；超过观测总量
的游标是错误。文本解码由宿主负责。

`task.closeOwner` 先封闭 owner，再取消请求。`task.ownerClosed` 在所有待处理任务的
终态发布之后回复，报告回收确认或者 `CLEANUP_UNKNOWN`。无法确认回收会污染 owner
并关闭私有通道，以便公开宿主终止其所属内核范围。污染的进程所有权保留至 teardown；
没有脱离所属范围的回收，也不创建替代内核。同一连接上的请求 ID 不可与 shell/file 操作冲突。

shell/task 回复共用单个 512 帧有界 writer。容量耗尽或物理写失败会通过独立持有的
控制端点关闭通道，包括最后输入帧之后异步完成时的失败。输入 reader 不会阻塞在发送
task 输出回复上。宿主 teardown 先中断控制端点，再 join 任务 worker、shell worker 和 file leaf。

常规 native workspace gate 包含以下任务断言：队列饱和、排队 deadline、owner 关闭顺序、
迟到准入、小数计时、结构化回收失败、真实关闭 stdin 与退出码 259、双流有界尾部、普通
后代回收、显式/提升 job 生命周期、定向取消，以及提升后硬 deadline 仍生效。标记 ignored
的子进程 fixture 由真实生命周期测试显式执行，并非跳过行为验证。

生产批准/runtime/script 准入、Jobs 移交发布、可恢复 spill，以及交错执行的跨平台性能
验收仍是独立工作。本协议切片不代表 #872 完成。
