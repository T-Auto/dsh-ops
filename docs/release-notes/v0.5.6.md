`0.5.6` 补丁版本，汇总了自 `v0.5.5` 以来的主要变更。

<h3 id="cn-v0.5.6">新增功能</h3>

- `PTC` 与 `OPS (PTC)` 新增工具披露设置：默认按需加载；选择全量后，首轮即可调用获准的工具和 `ops_result`，只读限制和全局动态工具开关仍然生效。 @Thatgfsj
- `ops_glob` 和 `ops_grep` 新增 `includeHidden` 选项，可搜索 `.github` 等点前缀目录；默认行为、显式排除和不跟随链接规则不变。 @BeiWay1145

### 体验优化

- OPS-PTC 的批量教学和提醒改为在模型步骤开始前以普通用户消息投递，不改写工具结果；教学只说明宿主报告的当前沙箱权限档位。 @Nicholas023
- 可继续的 PTC 读取给出下一步操作建议，自定义 PTC 集成不再把可加载但尚未加载的工具误报为缺失。 @Thatgfsj
- 未加载的 PTC 工具和未选中的发现能力分别指向 `ops_load_sdk` 与 `ops_discover_tools`；内置预设会话可用 `ops_status` 诊断自己的工具作用域。 @Nicholas023
- Bash 工具说明明确区分完整输出与截断片段，并说明 `spillPath` 不保证输出完整。 @T-Auto
- 合并可选 WSL 只读执行路径的准备步骤，减少 `wsl.exe` 启动次数，保留载荷校验与 Windows worker 回退。 @Nicholas023

### 问题修复

- PTC 预设在 OPS 替代工具可用时隐藏官方文件工具；Bash 替代执行器不可用时保留或恢复宿主允许的官方工具。 @Nicholas023
- 修复禁用或卸载 OPS 后无法新建会话的问题；仅在默认预设仍指向 `ops-ptc` 时恢复宿主默认值。 @Nicholas023
- 修复 Native 工具的事件与生命周期监听导致 `dsh-tui --resume` 无法恢复会话的问题。 @w21180239
- 修复 Windows 上受支持的 OneDrive 占位工作区和 WSL UNC 工作区被准备流程误拒的问题。 @Nicholas023
- 修复完全访问会话中工作区包含默认 `DSH_HOME` 时 Niubash 无法准备的问题，以及无效入口遮蔽系统命令、Bash 工具重复注册或回合中断后消失的问题。 @Nicholas023
- 修复使用从 Native 读取结果复制的转义文本做精确编辑时的匹配问题，并支持读取使用间接流长度的经典 xref PDF。 @Nicholas023
- Windows 文件写入保留并核验可恢复的扩展属性；独立 worker 遇到不支持的 Electron `.asar` 归档成员路径时会给出明确诊断。 @Nicholas023

The `0.5.6` patch release summarizes the main changes since `v0.5.5`.

<h3 id="en-v0.5.6">New Features</h3>

- Add a tool disclosure setting for `PTC` and `OPS (PTC)`: on-demand stays the default; full disclosure makes permitted tools and `ops_result` available on the first turn, while respecting read-only restrictions and the global dynamic-tools switch. by @Thatgfsj
- Add `includeHidden` to `ops_glob` and `ops_grep` to search dot-prefixed directories such as `.github`; defaults, explicit exclusions and link-following rules are unchanged. by @BeiWay1145

### Improvements

- Deliver OPS-PTC batching lessons and reminders as ordinary user messages before a model step, without rewriting tool results; lessons cover only the sandbox tier reported by the host. by @Nicholas023
- Give resumable PTC reads actionable next steps and stop reporting available but unloaded tools as missing in custom integration diagnostics. by @Thatgfsj
- Point unloaded PTC tools and unselected discovery capabilities to `ops_load_sdk` and `ops_discover_tools` respectively, and let built-in preset sessions diagnose their tool scope with `ops_status`. by @Nicholas023
- Clarify how to distinguish complete Bash output from truncated fragments and that `spillPath` does not guarantee completeness. by @T-Auto
- Reduce `wsl.exe` startups by combining setup for optional read-only WSL execution while retaining payload verification and Windows worker fallback. by @Nicholas023

### Bug Fixes

- Hide official file tools in PTC presets when their OPS replacements are available, and preserve or restore host-permitted official tools if the replacement Bash executor is unavailable. by @Nicholas023
- Fix new sessions failing after OPS is disabled or unloaded by restoring the host default only when the selected default still points to `ops-ptc`. by @Nicholas023
- Fix Native tool event and lifecycle subscriptions that prevented `dsh-tui --resume` from restoring sessions. by @w21180239
- Fix workspace preparation incorrectly rejecting supported OneDrive placeholder and WSL UNC workspaces on Windows. by @Nicholas023
- Fix Niubash preparation when a full-access workspace contains the default `DSH_HOME`, unusable entries shadowing system commands, and duplicate or missing Bash tool registrations after interrupted turns. by @Nicholas023
- Fix exact edits using escaped text copied from Native reads and support classic-xref PDF streams with indirect lengths. by @Nicholas023
- Preserve and verify restorable extended attributes on Windows file writes, and report a clear diagnostic for unsupported Electron `.asar` archive member paths in the standalone worker. by @Nicholas023
