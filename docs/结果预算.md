# 结果预算与会话生命周期

OPS 工作进程单次执行上限为 30 秒。同一宿主会话的 Native 与 PTC 共用先进先出的调用队列：
最多同时执行两次、等待八次。队列溢出返回 CALL_LIMIT，且无副作用。取消的等待调用不会启动；
获得执行资格后重新检查权限。Native 模型文本按转义后的字节计算，上限为 64 KiB；工作进程
传输收集上限另设为 128 KiB。规范数据缓存限额为每结果 10 MiB、每会话 100 MiB。三者分别计量。

引用缓存位置来自可信宿主元数据。Windows 使用真实沙箱提供者的会话临时目录及其专用写入能力。
PTC 仍通过宿主沙箱执行，Native 固定文件操作保持原有权限执行路径。完全访问模式仅使用宿主
提供的专用缓存准备能力，不准备工作区或请求工作区沙箱。旧版 Windows 宿主缺少该能力时，
完全访问模式不创建可选缓存；切换完全访问不会修复工作区 ACL 或增加工作区授权。已准备的会话
缓存仍可在当前权限绑定下复用。工作区写入模式保留旧版沙箱准备路径。无法准备缓存时，文件操作
继续返回有界且明确标注不完整的结果；创建引用则报告缓存不可用。
PTC 不会回退为无沙箱执行。

引用绑定当前活动会话、权限、凭据保护规则、操作根目录和生产工具。只接受当前可见且可执行的
生产工具及已获准执行的工具。权限模式变化会使原有绑定失效，包括收窄为只读。只读调用不会
创建缓存或更新 LRU。已有旧式审计引用保持独立的约定。

会话销毁立即使引用过期，取消等待及执行中的调用，等待执行结束，再按当前宿主权限清理经过
验证的快照和暂存文件。稳定锁及未知文件保留，审计数据不清理。只读模式或宿主服务不可用时，
物理清理可能无法完成；此时该根会连同失败原因（只读、授权变化、缓存授权、超时、EPERM）与
尝试次数登记在临时目录下的私有 pending 账本中，而不是被遗忘。之后恢复 workspace-write 授权、
下次启动或操作者命令会按有界指数退避重试；宿主保持只读期间不删除任何东西。内存中的新会话
随机标识保证重启后不能重新使用磁盘残留引用。各组件共享生命周期；最后一个 Native/PTC 所有者
卸载时清理剩余会话。清理为内部操作，模型不能通过工具参数发起。

native purge 有意保留根目录、`s-<hash>/` 作用域目录与稳定锁 inode，而根在首个非只读调用时就
已 eager 创建。因此宿主侧清扫会在启动时与最后一个所有者卸载后回收这些根：只处理名为
`dsh-ops-results-<64 hex>`、归当前用户所有、权限私有、非链接，且内容仅限 `s-<64 hex>/` 作用域
目录（内含 `lock`、`<uuid>.json`、`<uuid>.tmp`）的目录；出现任一未知条目即整个根跳过并报告。
本进程仍在引用的根排除在外；根须空闲满 `resultCache.maxAgeMs` 才可处理（本进程创建的根在卸载
清扫时跳过该宽限）；单次 pass 受根数量与墙钟预算约束，删除失败立即停止。默认只回收不含快照
数据的根——空根，或只剩 lock 的作用域目录。`MAX_SESSION_BYTES` 始终是单个缓存根的“单 nonce
配额”，不作为全局预算：聚合上限是 `resultCache.maxRoots` 与 `resultCache.maxTotalBytes`，二者
默认 0。它们是报告阈值而非删除预算——仍含快照数据的根只会被标为 blocked（超龄、活跃或超预算），
宿主侧清扫永不删除；只有经过授权的会话 purge 或其延迟重试才能回收这些数据。
`dsh-ops result-cache status` 报告清单，`dsh-ops result-cache reclaim [--apply]` 预览或执行同一次
有界清扫。

## Native 与 PTC 引用分页

Native、发现与 PTC（包括继承源）租用同一 canonical result 定义；所有呈现的输入 schema 均为 put/page/release，但 schema 不授予写权限。Native 仅可对自有 ref:// 执行 page/release，不接受 audit ID 或 purge。put 在任何 IO 前验证：parent 必须匹配仍在执行的根 run_code token，并保持相同 agent、rootCallId 和精确 toolSet，且当前呈现允许 PTC。公开事件证明合法嵌套和当前 PTC 准入，不是加密执行器证明；Native 嵌套、伪造/失效 token 均不授权 put。put 仅写会话私有缓存，保留大小、格式、凭据与沙箱检查。

两种投影省略 root 均使用实时会话 cwd；切换目录后须显式传原 referenceRoot。这替代共享 result 过去的 PTC 工作区根默认值；工作区绑定的 batch 审计必须显式传 root。跨会话/root、权限改变或 producer 隐藏均拒绝，release 只删缓存观察而非业务文件。卸载一个消费者保留其他 grant；真实授权/来源变化后须重新 resolve。

默认 offset=0、limit=64、maxBytes=16384；范围为 1–512 行、512–65536 字节。equals 先过滤，再由 fields 投影；offset 计过滤后的存储行。ttlMs=0 默认跟随会话，put 最长七天；createdAt 为 Unix 毫秒。整个 put 请求至多 2 MiB，物理快照至多 10 MiB。

Native 转义后文本至多 64 KiB。仅 displayComplete=true 才可跟随 nextOffset，否则在相同 offset 缩小 limit/maxBytes 或 fields。pageComplete 仅说明存储行分页；source 的原操作范围、capturedItems/captureComplete 独立。tagged-json-v1 的 item-json-chunk 按 index/byteOffset 拼接 text，最后 complete=true 后才 JSON.parse；单个尾块不是完整项。分页结束不补全不完整扫描。
