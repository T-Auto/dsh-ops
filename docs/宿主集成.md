# 宿主集成排查

[English](host-integration.md) | 中文

以下检查区分插件配置、宿主展示与提供商传输问题，不代表已修复未复现的 Desktop 卡死，
也不代表已修复旧会话的历史记录。

## DSH 0.2.2 发布迁移

文件读写与 result 共享 scope-owned canonical 来源，不再用 Native/PTC 各自 shadow 定义。Native 保留独立渲染与上下文读取证据，执行事实在 Outcome.data；cwd、凭据、CAS、沙箱仍走既有权威桥。PTC 专属 jobs 与 load_sdk 独立。

条件与 prompt assembly 不改注册；pending 选择在 step/end 提交。不变权限保持定义身份；真实 grant/来源变化保守替换共享注册：**同一来源下其他 agent 已捕获的 toolSet 也会失效**，宿主在副作用前报 UNKNOWN_TOOL，下次 resolve 恢复仍有资格者。不同来源独立。这是可用性限制，不是跨 agent 快照隔离；旧步不获得新 grant，禁止自动重放。

迟到的外部祖先源保留原定义、条件与限制，fallback 退役且不复制进子级自有层。执行期间任一已捕获 grant 撤销均否决调用；provider 不响应 abort 时有界返回 RESULT_UNKNOWN/unknown effects，应检查结果而非自动重试。共享 result schema 与 PTC-only put 边界见[结果预算](结果预算.md)。


0.5 中，开启原版工具替换不保证条件性工具从模型工具表消失。OPS 对应项采用条件准入时，原版注册仍可见；只有同一已捕获步骤 toolSet 准入该对应项且消费者当前仍有权限时，OPS 才在分派时拒绝原版调用。对应项缺失、撤销或尚未就绪时，不得连带禁用原版工具。安全的无条件常驻替换仍可使用宿主限制。OPS 不包装原版定义，也不在准入条件或提示词组装中隐藏工具。

宿主发布会话 append 时可能拒绝注册表写入。OPS 每个宿主根共享一次冷却（25、100、400，之后 1000 毫秒），遇到首个拒绝即停止，并保留待注册与待撤销操作；恢复不依赖新的会话事件。延迟工具在实际注册前不可用，现有执行守卫仍拒绝已撤销权限。普通配置错误不会重试；警告保留被抑制次数并报告恢复，作用域卸载会取消尚未完成的注册。

保留的显式 `hide-official` 行仍采用严格语义：每个选中对应项都必须是当前步骤准入的精确有效 OPS 定义，同名外部定义不能满足就绪条件。延迟初始化遇到永久错误时拒绝等待中的就绪 promise 并触发挂载回滚，不进入重试循环。

共享 result 适配器仅在验证过的活动 `run_code` 父调用中保留 PTC 的 `j-` batch 审计与旧 `r-` 快照访问。worker 仍校验会话、根目录及根身份，审计记录不能 release；Native 仅允许 `ref://` page/release。活动准入凭证贯穿目录、confinement 与缓存准备，并在 worker 分派前立即复核；检查失败或权限撤回时，在分派前无副作用地拒绝工作。公开提示词变更通知不标明作用域，因此同一宿主中其它作用域的提示词更新也可能保守拒绝正在准备的 PTC 调用，不会自动重放。

PTC 引导仅在公开文本 waterfall 确认 executor 的 `tools:ptc-only` 段后填充，共享文件工具的可调用名称不代表展示模式。启用 PTC 行必须保持完整 Native 提示词和 wire 工具表不变，同时保留 PTC 组装中已准入的 SDK。

## 源码职责

`src/presets/` 管理内置预设默认；`src/consumer/` 通过同一个流程装配内外消费者。作用域发布位于 `src/publication/`，Native 与类型化 PTC 投影位于 `src/projections/`，共享 worker 执行位于 `src/execution/`。这些是内部路径，不是第三方公开导入入口；见[内部架构](内部架构.md)。

## 白名单无法隐藏 `ops_bash`（#380）

固定版本的 DSH tools API 中，`tools.restrict()` 只遮蔽继承的注册项，agent 自有注册项
单独解析。OPS 在 agent 作用域发布 Bash，使定义跟随该会话的权限与服务。因此不能认为
继承工具白名单也会移除 `ops_bash`。同一白名单能隐藏全局注册的文件工具，并不能证明它
能隐藏会话自身的 shell。只读沙箱也是文件系统权限模式，不承诺命令工具全部不可见。

要停止 OPS Bash 发布，在单个 `dsh-ops` 行的内置分区设置 `bash: false`，或在显式消费者设置 `shell: false`。合并到已有配置，保留其他键：

```yaml
standard:
  bash: false
```

检查有效配置中的所有消费者：另一个显式绑定仍可能为自己的预设发布工具。
通过宿主设置或 profile 生命周期应用变更，再验证新会话的工具清单。该开关只控制 OPS
Bash，不会禁用其他独立安装的命令工具。

按 preset 禁止命令，需要能覆盖自有工具的宿主执行策略，或经过验证的作用域挂载方案。
仅启用某个模式行，尚不能作为隔离保证：该行挂载时也会枚举已存活的 agent。
依赖此方案前，应验证允许与禁止的 preset、已有与新建会话，以及实际调用被拒绝的结果。
OPS 不会改写共享工具注册表，让继承掩码强行作用于自有工具。

## 提供商拒绝旧会话中的 `tool_addition`（#367）

OPS 通过宿主注册表发布工具定义；DSH 记录工具集变化并序列化提供商消息。OPS 不构造
`tool_addition` 块，也不选择它在线路消息中的角色。因此，报告中的
`tool_addition blocks can only be in system messages` 属于宿主/提供商序列化边界，
即使触发条件是一次 OPS discovery 工具变化。

进行有限诊断时，先确定配置，再新建会话，并在该次运行中保持工具集稳定。需要的
`alwaysLoaded` discovery 能力应在创建会话前配置，运行中避免修改选择或组件设置。
禁用 discovery 可以去掉该渐进发布触发器，但也会失去只能通过 discovery 获得的能力。
这不会修复保留的历史，也不保证适配所有提供商。

若仍被拒绝，保留准确的宿主/插件版本、提供商/模型、request ID、新增/移除工具名，
以及能展示错误块的最小脱敏消息角色片段。宿主/提供商适配器需要这些证据；改 OPS 工具名
或修改历史消息角色，不是插件侧序列化修复。
[议题 #367](https://github.com/T-Auto/dsh-ops/issues/367) 记录了该触发场景。

## 缺少 `ops_discover_tools`（#346）

先用应用自己的 CLI 检查它实际使用的 profile。Desktop 使用自带 CLI；普通 CLI 不能管理
保留的 Desktop profile。非 Desktop 测试 profile 的示例：

```console
dsh plugin --profile ops-test add dsh-ops@latest
dsh --profile ops-test --dump-config
dsh --profile ops-test --dump-config-schema
```

验证未发布修复时，将 `@latest` 换成目标版本或本地打包产物。把 `--profile` 放在 `add`
及包管理器参数之前。有效配置中应有启用的单个 `dsh-ops` 行，Native discovery 分区、全局与对应预设动态开关开启，或有启用发现的显式集成。先检查自定义 `presets`、保存覆盖及重复绑定，不要直接补旧行。旧 profile 缺少发现与已启用行发生发布停滞是不同问题。

展示模式也影响工具：普通 Native 作用域使用 `ops_discover_tools`；PTC 作用域通过宿主
`run_code` 展示使用 PTC SDK loader。应检查具体作用域的装配工具和展示模式，不只查看
全局注册表或提示词段名称。discovery 段为空本身不足以确定原因。

0.5 adapter 面向 DSH `>=0.2.2-rc.1 <0.2.3-0`，不再支持旧宿主。宿主导入继续集中在 `src/adapter/dsh`，保留 type-only 声明和延迟运行时加载。0.2.2 宿主选择 executor，并在 prompt assemble 与 pre-step 之前捕获 `ResolvedToolSet`。稳定的条件注册按已提交选择在下一步开放发现/PTC 工具；提示词回调不发布工具。请求指引和替换 guard 使用捕获的准入集，注册态诊断通过公开 `definitions()` 读取而不复制 schema。缺少实时工作目录服务属于基础设施错误，不能回退到原始 header 作为执行目录。兼容证据必须标明真实依赖图和实际检查，版本字符串本身不构成运行验收。

#346 原始报告也包含“行已启用，但发布链停滞”的情况，上述 profile 检查不能证明它已被
修复。若行已启用而预期的作用域工具仍缺失，应提供最小 profile、准确版本、Native/PTC
模式、受影响作用域的 schemas，以及带时间信息的生命周期轨迹以定位尚未完成的发布。
重启/新建会话结果可用于比较，但不能证明无限热挂载停滞不会再次发生。
