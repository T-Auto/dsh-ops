# 0.4.0 手动验收

English: [manual acceptance](manual-validation.md). 以下是操作者检查清单，不代表每种 UI 或部署均已验证。使用一次性 profile 和工作区，记录命令、实际结果、平台/宿主版本及候选 commit。仅查看设置页面不应安装或升级真实运行时。

## 构建与发布证据

按[贡献指南](贡献指南.md)构建 worker，并在 Windows 提供已校验 Bash fixture，运行完整发布门禁；所需运行时被跳过不能计为通过。单独运行[BM-01–05](基准门禁.md)，保留逐项通过/失败/阻塞状态与原始结果。采用明确批准的标准：BM-01 在固定无损工作负载上相比 OPS 0.3.x 至少减少 40% 字节，官方读取另列对照；BM-03 对文件/发现 schema 执行 ≤400 token 上限，并保留 Bash 启动常驻。同时记录范围分数与完整供应商总数，核验含可用 Bash（Windows 固定载荷或宿主 bash）的确切默认工具清单。不能用更小工作负载、缺少 Bash 或功能 CI 通过代替实测。

## Profile 与配置

1. 用含带名称覆盖、混合开关和其它插件配置的已保存六行 profile 升级并重启两次；确认七个唯一 OPS ID、旧文件行名称与配置、显式开关均保留，并新增 discovery。
2. 新 profile 默认 file/PTC/discovery 开，三个平台的 shell 都开，panel/TUI/替换关。启用新 panel 行后观察新事件；关闭后排队采集停止，不执行最终归并。旧配置显式 capture:false 必须保持不采集，直到操作者更改。
3. 内置表单保存合法值后重启验证；未知键、错误类型或过期版本不覆盖已保存值。旧 file/root/shell 的 null 配置保持原默认值。关闭的行先开启才可编辑。

## 工具发布与结果

1. 检查首次实际供应商请求：Native 有 read_files/discover_tools 及可用的 Bash（Windows 固定载荷或宿主 bash），高级文档 schema 不可见。发现后仅所属下一请求可见，当前轮诊断或兄弟 agent 不可见。
2. PTC 常驻 inspect_local_file/result/load_sdk；通过 ops_load_sdk 加载允许的高级 API，核对下一 SDK 快照及类型化 Outcome 的 status/data。保留操作者显式允许池；工具可见不代表授予文件权限。
3. 一次读取三个文件范围，精确还原转义行，核对逐文件错误、待处理输入与文件内续读。一个文件五处编辑使用修订值；过期 CAS 或重叠编辑不得更改内容，部分输出不得冒充完整。
4. 读取 CSV/TSV、DOCX 和受支持 PDF 文本层，再加入后续畸形/不支持内容；允许保留安全前缀，但 total/revision 只来自稳定完整扫描。分别核对扫描、请求页、展示与引用捕获完整性及排除范围。
5. 只选择已就绪的确切 OPS 官方替代项；read 要求 inspect_local_file，不能用 read_files 代替。同名外来工具不能满足就绪条件。

## 权限、运行时与卸载

分别测试只读、工作区写与完全权限。凭据保护读取须拒绝；只读模式拒绝写入，工作区写模式拒绝越界写入，不泄露被拒路径/内容且不改文件；完全权限遵循其较宽的写入授权。宿主允许的普通外部读取是允许对照，并非“工作区读取沙箱”失效。权限变化、取消和卸载须停止或失效自身工作，仅撤回本插件注册。

Bash 保留宿主 command/description/cwd/timeout 契约、审批、jobs 与输出类型；默认120秒，上限600秒。无 jobs 时不公开后台选项；有 jobs 时通过宿主工具收集或停止，超时提升不能再次执行命令。Windows 受限模式仍有文档注明的部分约束与精确 MSYS 兼容要求。

运行时管理先显示计划，再显式执行；启动后取消可能影响未知。Git/managed 选择仅改草稿，保存后生效。PowerShell 升级针对标准宿主安装，要求重启，并提示操作者检查自定义 pwshPath。不能因打开页面或传输断开而宣称安装成功。

兼容 dsh-TUI 存在时单独记录终端验收；缺少宿主时，相关可选套件必须注明跳过，合成注册测试不能代替真实终端验收。发布审查须保留所有失败与跳过。
