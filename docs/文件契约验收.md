## 准入与归属

- Native standard 准入 OPS read/glob/grep 替代并撤下相应官方名称；保留 `edit` 与
  `read_image`。既有替代测试覆盖就绪状态、已捕获步骤、限制、同名注册与卸载。
- 两个内置 PTC 模式明确配置为**不替代文件工具**。SDK 保留官方 read/glob/grep/edit，
  同时包含已选中的 OPS 方法。审计真实执行两种 glob 的 nested 调用，而顶层请求始终只有
  `run_code`。这是预设策略，不是 #787 的 Native「可见但调用被拒」。
- 卸载恢复原工具面；未接入 OPS 的原版 PTC 不增加 OPS 提示或 SDK。关闭 batching 不投递
  教程或提醒，由生命周期套件验证。运行时版本只在显式诊断中返回。

## 保留的宿主依赖

#865 保持开放：公共 Outcome/page/reference 声明去重及随输入模式收窄返回类型仍需宿主支持。
固定宿主逐个渲染输出 schema，未提供公共声明钩子。见 [SDK 按需加载](PTC按需加载.md)。

#866 保持开放：宿主 filesystem 插件的 `tool:read` 指引基于注册表可见性而非当步准入，
真实宿主回归复现了过期名称。OPS 自有明确调用指引已对照 Native 可调用名称验收。
见 [Native 输出](Native输出.md)。

本改动不重写宿主或 profile，不部署、不发布、不向上游发 issue，也不执行付费基准。
