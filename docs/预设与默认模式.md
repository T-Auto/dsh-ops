# 预设与默认模式

[English](presets.md) | 中文

`ops-ptc` 是 OPS 的第五个内置增强模式。它不是一个完全新写的 preset，而是宿主官方 PTC 预设的一个
补丁片段：插件只增强宿主已经声明的预设，所以 `ops-ptc` 需要自己声明一行 `@deepseek-ai/dsh-agent-preset`，
再在单行 `dsh-ops` 里用同名分区发布工具面。本页说明这个片段怎么来、怎么装、怎么设为默认，以及它与
官方 PTC 的差别。

## 片段与同步脚本

仓库里的 `presets/ops-ptc.patch.yml` 是生成文件，不要手改：

- 上游来源：`@deepseek-ai/dsh-web-app/presets/ptc.patch.yml`（宿主随包的官方 PTC 预设）。
- 生成器：`scripts/sync-preset-ops-ptc.mjs`。它按锚点做文本替换，因此 `!!js` 表达式、注释和表达式形式
  都原样保留，最后再解析一遍做自校验。
- 与上游的差异只有身份：行 id 变成 `preset-ops-ptc`，preset 的 `id` / `name` / `description` / `order`
  变成 `ops-ptc` / `OPS (PTC)` / 一句描述 / `6`（order 6 让 OPS PTC 排在官方行之后）。
  `config.plugins` 与上游逐字节一致，所以压缩组仍是官方 `compaction-basic`，不引入 `dsh-compress-codex`。
- 文件头记录了来源与 `sha256`，同步脚本写入新摘要。

常用命令：

```console
node scripts/sync-preset-ops-ptc.mjs              # 重新生成片段
node scripts/sync-preset-ops-ptc.mjs --check      # 校验漂移；漂移时退出码 1
node scripts/sync-preset-ops-ptc.mjs --stdout     # 只打印，不写文件
node scripts/sync-preset-ops-ptc.mjs --source <ptc.patch.yml 或其目录> [--out <file>]
```

源解析顺序是 `--source`、`DSH_WEB_APP_PRESETS`、`@deepseek-ai/dsh-web-app/presets/ptc.patch.yml` 的包解析、
向上查找 `node_modules`，最后是已安装的 `@deepseek-ai/dsh` 自带副本。解析不到源是失败而不是静默通过。
升级宿主后重新运行脚本并审阅 diff；`--check` 适合放进本地校验流程。

## 随包安装

安装后 `presets/` 会随包发布（`package.json` 的 `files` 包含它），bundle 的 `dsh.bundle.patch` 是数组：

```yaml
dsh:
  bundle:
    patch:
      - ./cordis.patch.yml
      - ./presets/ops-ptc.patch.yml
```

两个 patch 文件按顺序叠加，因此 `ops-ptc` 预设行随 bundle 层自动声明，出现在宿主「Agent 预设」选择器里，
不需要用户手写 YAML。升级宿主后片段可能过期，此时用上一节的脚本重新生成。

已有 profile 若要手动并入片段，把 `presets/ops-ptc.patch.yml` 里的 `- insert:` 条目追加到
`$DSH_HOME/profiles/<profile>/cordis.patch.yml` 即可；不要重复插入同名行，补丁按 id 匹配，重复声明只会互相替换而不会合并成两行。

## 设为默认模式

`dsh-ops` 的 bundle patch 当前在 `cordis.patch.yml` 末尾带一个 id 定向覆盖，把默认预设指向 `ops-ptc`：

```yaml
- id: agent-preset-registry
  name: '@deepseek-ai/dsh-agent-preset-registry'
  config:
    default: ops-ptc
    selectedDefault: ops-ptc
```

仓库随包的 bundle 层带这段覆盖，但它是否生效取决于安装后实际合并的 `cordis.patch.yml`；安装过程不改写用户 profile，用户自己的覆盖或设置页选择优先。两种设置方式：

- **bundle 层（随包默认）**：上面这段覆盖只在 `dsh-web-app` bundle 层之后应用时命中 `agent-preset-registry`
  行。没有该行的 profile（例如 headless）每次启动会打印一条
  `patch: entry "agent-preset-registry" not found` 警告并跳过，非致命。
- **profile 层（用户自选，推荐）**：把同样的片段追加到 `$DSH_HOME/profiles/<profile>/cordis.patch.yml`。
  profile 层最后应用，会覆盖 bundle 层；这也是你在官方 PTC 与 OPS PTC 之间切换默认值的地方。

关于字段：`default` 是部署默认，决定没有用户选择时新会话用哪个预设；`selectedDefault` 是易变的用户级
默认，新会话解析时优先于 `default`，宿主的「Agent 预设」设置页写入的就是它。**id 定向 patch 不深合并**，
它整体替换目标行的 `config`，所以改一个键也要把另一个键原样重述，否则会被清掉。

### 风险与回退

- 先把预设行声明好，再改默认。注册表恢复会话时按当前定义解析，预设行缺失或激活失败会让新会话无法使用
  该预设；删除覆盖或改回 `standard` / `ptc` 即可回退。
- 已存在的会话保留它们已经绑定的组合，改默认只影响之后新建的会话；在设置页改选择同理会写成
  `selectedDefault`。
- 宿主未来给 `agent-preset-registry` 增加字段时，id 定向覆盖会把那段 config 整段替换掉；这是把默认值写在
  bundle 层的主要代价。更稳妥的做法是只在自己的 profile patch 里覆盖，并接受升级后重新核对。

## 与官方 PTC 的差别

| 项 | 官方 PTC（`ptc`） | OPS PTC（`ops-ptc`） |
| --- | --- | --- |
| preset 声明 | `dsh-web-app` 的 `presets/ptc.patch.yml` | 本包的 `presets/ops-ptc.patch.yml`（行 id `preset-ops-ptc`） |
| 发布面 | 官方 PTC 工具 | 与 `ptc` 分区相同：真实 PTC 呈现下的 `run_code` 加同栈类型化 SDK 文件工具 |
| 压缩 | 官方 `compaction-basic` | 同为官方 `compaction-basic`，不引入 `dsh-compress-codex` |
| 批量调用提示 | 无 | `batchingGuidance`：代码默认 false，随包 `ops-ptc` 节置 true；可在 YAML 关闭 |
| 单行配置分区 | `ptc` | `ops-ptc`（键与 `ptc` 相同，另加 `batchingGuidance`） |
| 排序 | order 2 | order 6，排在最后 |

同一套工具面开两个模式的意义就是对照臂：`ptc` 保持官方预设不变，`ops-ptc` 用同一批 API 与压缩策略，
仅多出可开关的批量调用提示。提示只在同一轮对同一规范化路径连续 3 次写入后注入一次，通过工具结果的
延迟上下文送达，不改系统提示词前缀；开关语义与触发细节见[配置参考](配置参考.md)的 OPS PTC 模式节。
