# 设计决策：PTC 预设下隐藏官方文件工具

日期：2026-11-15
状态：已接受
范围：`src/publication/ptc.ts`、`src/publication/replacements.ts`、`src/consumer/mount.ts`、`src/presets/builtin.ts`、`src/integration/index.ts`

## 背景

`hideOfficialTools` 的文档语义是“隐藏本模式替代的官方文件工具”。实际上它对所有 PTC 模板预设（`ptc`、`ops-ptc`、自定义 PTC preset）都不生效：`MODE_PLANS` 为它们声明 `nativeFiles: false`，而 `replacementTargets` 用 `config.hideOfficialTools && plan.nativeFiles` 作门，因此目标表中永远只有 Windows shell 名字。`mountReplacements` 确实已挂载（Windows 下 targets 非空），但从不处理 `read`/`glob`/`grep`。

PTC 投影保留官方 SDK 绑定（`tools.grep`、`tools.read` 等），而 `ops_*` 按需加载，因此开关开着时模型仍可能选用更弱的官方 API。

这被定性为缺陷而非策略：`docs/文件契约验收.md` 中的验收记录描述的是当时的配置，而开关对用户的承诺是覆盖它所替代的文件工具。

## 决策

1. 修复现有 `hideOfficialTools`；不新增开关；默认值不变。
2. 按运行 PTC 呈现判定，不按预设 id：`ptc`、`ops-ptc`、自定义 PTC preset。`minimal` 不卷入。
3. 隐藏集合 = `RAW_OFFICIAL_REPLACEMENTS` 的键（当前 `read`、`glob`、`grep`），随表扩展。
4. `write`、`edit`、`read_image` 保持可见。
5. 载体：扩展 `mountReplacements` 的 shadow `when`（方案 B），不使用 `ctx.tools.restrict`。
6. `replacementTargets` 的门改为 `plan.nativeFiles || plan.ptc`；integration 路径覆盖两种呈现。
7. 可达性信号由 PTC 发布面给出：`permitted ∧ (resident ∨ allowedApis)`，再加一道存在性校验（发布器确实注册了 counterpart：`tools.get` 非空且 `publicationAdmission !== undefined`）。排除 `selected`，`publicationAdmission` 不求值，因此加载 SDK 不会改变判定。
8. `mountPtc` 返回 `PtcServability` accessor；`apply` 保持 `void`；未 attach 的 agent 返回 `undefined`（fail-open）。
9. 每个 agent、官方工具名与状态各记录一次；发布面探测失败时 catch 并 fail-open（保留官方），记录一次 warn。宿主行为已实测：`when` reject 会让整个 step 解析失败（`cannot resolve availability of tool`），因此 catch 是必须的。
10. 内置模式与 integration 路径都修改。
11. 测试：完整矩阵（翻转现有断言，新增 mixed-tree 与配置矩阵）。

## 证据

real-host 探针（真实 `mode-ptc` 组件 + NodePtc + 根层注册官方 `read/glob/grep` + `mountPtc` 的 shared-file 发布）结果：

| 阶段 | admitted | `tools:sdk` 含 `grep:` | SDK 字节 |
|---|---|---|---|
| before | `read, glob, grep, ops_inspect_local_file, ops_load_sdk` | 是 | 8749 |
| agent 层同名 shadow + `when:false` | `read, glob, ops_inspect_local_file, ops_load_sdk` | 否 | 8676 |
| 恢复（dispose） | 完整 | 是 | 8749 |

同名 shadow 会同时从 `definitions` 与 SDK 段移除官方工具，且可逆。

## 实现

- `mountPtc` 返回 `PtcServability { servable(agent), isPtc(activation) }`；未 attach 时 `servable` 为 `undefined`，否则为满足 `permits(agent, api) && (resident.has(api) || allowedApis(agent).includes(api))` 的原始 API 集合。
- `ReplacementPublication` 新增可选 `ptc` 字段。在 `when` 中，于 `keepOfficial`/gate 检查之后、宿主 counterpart 检查之前，插入 PTC 分支：原始 API 在可服务集合中且当前 activation 为 PTC 时隐藏官方名字。
- PTC 分支只作用于 `RAW_OFFICIAL_REPLACEMENTS` 的键（绝不处理 `pwsh`）。
- Native 消费者不传 `ptc`，旧路径逐字节保持不变。
- `applyResolvedMode` 与 integration 路径的 `replacementTargets` 门都改为 `nativeFiles || ptc`。

## 后果

- 行为变更：升级后，`hideOfficialTools: true`（默认）的 PTC 会话不再看到官方 `read/glob/grep`；模型需通过 `ops_load_sdk` 加载 `ops_*`。已写入 CHANGELOG；可用现有开关关闭。
- `write`、`edit`、`read_image` 不受影响。
- 未 attach 或被收窄的 PTC 投影保留官方工具（fail-open）。

## 后果：首个 resolve 的时序

发布面异步 attach，在此之前 `servable` 返回 `undefined`，因此 PTC 会话的第一个 resolve 可能仍显示官方工具，下一次 resolve 才隐藏。这属于 fail-open 契约而非回归；`notePtc` 会记录 `unattached`，窗口可观测。

## 未决风险

已由探针解决：`when` reject 会让整个 step 解析失败（`cannot resolve availability of tool "read"`），既不是 fail-open 也不是静默隐藏。因此 `replacements.ts` catch 探测失败并保留官方工具。已知并接受的风险：可达性来自发布面池（`permitted ∧ (resident ∨ allowedApis)`），而非 `publicationAdmission`；此后若发生宿主级发布拒绝，属于 PTC 发布器故障，由 PTC 生命周期套件覆盖，不由隐藏决策负责。
