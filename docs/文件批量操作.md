# 文件批量操作

English: [file-batching.md](file-batching.md).

`ops_read_files` 在一次临时 worker 调用中读取 1–32 个 UTF-8 文件范围。相对路径始终基于本次调用的
会话 cwd。每项需要 `path`，可指定从 1 开始的 `offset`（默认 1）与 `limit`（1–10000，默认 200）。
与旧检查工具不同，offset 0 无效。未知字段、非法范围和无效描述会拒绝整个请求。二进制数据应使用
文档/二进制读取器，或通过 `ops_inspect_local_file` 的 `view: "hex"` 查看；不会有损解码。

```json
{"files":[{"path":"src/index.ts","offset":1,"limit":80},{"path":"README.md","offset":10,"limit":40}]}
```

结果的 `items` 包含逐文件的版本哈希、字节数、物理行数、行内容与完成状态。空文件为零行，CRLF
只算一行，末尾 LF 不产生虚构行。不存在、不可读或编码错误的文件产生独立错误项，保留其他文件的
成功结果。宿主会在启动进程前检查所有凭证路径，只要有一项受保护就拒绝整个请求；worker 还会逐项
验证路径并拒绝符号链接/junction。只读调用不创建审计或缓存文件。成功项使用读取前观察到的版本更新
宿主的“读后编辑”记录；失败项与尚未读取的项不更新该记录。

所有平台都将完整路径组件 `.dsh-ops` 视为保留名，忽略 ASCII 大小写；绝对路径、会话 cwd 上方的
祖先组件及尚不存在的创建目标也适用。公开文件读取（包括文档读取器、`stat`、`diff` 及每个
`read_files` 项）、写入、编辑、复制、移动和删除均以 `PATH_RESTRICTED` 拒绝；复制和移动同时
检查源与目标。显式指定的搜索/替换路径遵循同一规则。普通目录搜索仍排除隐藏审计项，不将这种
排除视为覆盖缺口。`.dsh-ops-backup`、`.dsh-ops.json` 等近似名称不是保留名，但仍受通常的隐藏
搜索排除规则约束。此公开路径限制不阻断可信的 batch plan/run/resume、审计分页及结果/缓存生命
周期 API，也不对绕过公开文件工具写入的审计记录提供真实性认证。

`nextIndex` 指向输入数组中首个未返回项，`pending` 是剩余项数。继续读取时提交原始 `files` 数组的
剩余片段。每个已返回文件还有独立的 `complete` 与 `nextOffset`，表示该文件尚未读取的行。只有所有
文件均已完整读取、没有错误且没有待处理项，顶层 `complete` 才为 true。`pending: 0` 的部分结果仍
可能需要逐文件续读；必须检查两层完成状态。

worker 按转义后的完整响应限制为 96 KiB，包含路径及元数据；Native 内容块还有 64 KiB 的显示上限。
超长行可返回前缀并带上 `truncatedInLine`、`bytesTotal`、`bytesOmitted`；续读位置保留在该不完整行。
使用 hex 视图按 16 字节一行恢复尾部。显示预算截断时，应缩小原始范围重读，不能跳过未显示的内容。
Native 输出文件标题、物理行号、逐文件错误与续读提示；程序化结果保持结构化数据。

`ops_edit_file` 对**单个** UTF-8 文件原子应用 1–100 段修改。参数包括 `path`、读取/stat 得到的准确
SHA-256 `expectedRevision` 与 `edits: [{oldText,newText}]`。每个非空 `oldText` 必须在同一原始字节中
唯一出现；重叠、歧义或版本过期会在发布前拒绝全部修改。空 `newText` 表示删除。CRLF/BOM 需显式
保留。`dryRun: true` 仅预览相同回执；只读策略仍拒绝写入工具。这不是跨文件事务。

它共享 `ops_edit_file` 的 no-follow、CAS 与平台元数据保护，返回包含版本、修改计数、字节/行数及
警告的短回执，不回显替换内容。重试前必须检查 `error.effectState`；该工具不会标记为并发安全。
