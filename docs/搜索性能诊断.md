# 搜索性能诊断

English: [search-performance.md](search-performance.md).

搜索在每次请求开始时准备 include/exclude glob 的路径段。每个候选文件仅拆分一次相对路径，
继续使用原有通配匹配器。该变化消除重复的模式分配，不改变遍历顺序、元数据检查、no-follow
打开、凭据排除、扫描预算、精确总数、提前停止或续页指纹。

在 **worker 进程环境** 设置 `DSH_OPS_PROFILE_SEARCH=1`，会向 stderr 输出一行以
`dsh-ops-search-profile ` 开头的诊断 JSON。它是开发诊断，不是工具参数或结果字段。
未设置该变量时，不采集阶段时钟，也不输出诊断行。诊断仅包含阶段名、调用次数和累计纳秒，
不含路径、查询模式或文件内容。宿主可能捕获但不展示 worker 的 stderr；下述直接调用 runner
给出了可复现的收集边界。

| 阶段 | 测量内容 |
| --- | --- |
| `walkTotal` | 整个有界遍历，包含回调及下列子阶段。 |
| `globCompile` | 请求级 include/exclude 分类和路径段准备。 |
| `relativeMetadata` | 相对持有目录句柄的条目元数据查询。 |
| `absoluteMetadata` | 原有链接/reparse 检查使用的绝对路径元数据查询。 |
| `globFilter` | 候选相对路径拆分和通配匹配。 |
| `pathValidationAndOpen` | 从绝对根重新校验路径，并通过受保护方式打开文件。 |
| `readIo` | 各次读取，含最终返回零字节的读取。 |
| `contentHash` | 对完整的有界文件缓冲计算续页身份摘要。 |
| `matchAndResults` | UTF-8 转换、匹配、上下文提取和结果页构造。 |

缺少某阶段表示未执行。`walkTotal` 已含其它阶段，不能再与它们相加。目录枚举、打开目录、
元数据指纹及其它管理工作仍包含在该总量中。worker 初始化、最终序列化、进程启动和宿主派发
不在此总量边界内。计数用于定位后续调查对象，不能证明某项权限检查可以安全删除或缓存。

## 复现前后对比

构建两个 release worker；构建第二个之前保存第一个二进制。二者必须带相同 profiler。
本次变更的第一个仅诊断提交保留旧匹配器，后续提交才改变请求级准备。在仓库根运行：

```console
node bench/search-profile.mjs BEFORE_WORKER AFTER_WORKER CORPUS_ROOT > search-profile.json
```

runner 固定语料内容身份，记录 worker SHA-256 和环境，交替调用顺序，保留首次样本和后续
两次预热，然后每种查询测量五次。`DSH_OPS_PROFILE_SAMPLES=1..20` 可调整实测次数。
进度写入 stderr，完整报告写入 stdout。查询覆盖精确计数的 TypeScript grep、提前停止 grep、
无过滤无命中和 glob。每次进程超时为 35 秒，原有协作式扫描预算仍为 30 秒。每次调用保留错误、
结果摘要、覆盖信息和阶段计数；结果不一致或语料变化会使 runner 失败。

语料身份包含常规文件排序后的相对名与内容摘要，排除点开头条目、依赖/构建目录及链接。
这仅是输入身份，不保证每个文件可搜索：超大文件、非法编码、凭据及运行时缺口仍由实际覆盖
报告表达。报告不写出语料正文或文件名。请对稳定、可信的本地语料运行；清单遍历仅属于仓库诊断。

先核对查询、结果摘要与覆盖范围相同，再比较时间。`exactTotal: false` 少扫描后续内容且只返回
下界，不能当作相同工作量的精确计数提速。首次样本不等于受控冷缓存实验。机器负载、文件系统/
缓存状态和杀毒扫描可远大于少量分配节省。CI 校验功能契约和诊断隔离，不设置墙钟时间门槛。

不变的完整性和续页规则见[搜索覆盖范围](搜索覆盖范围.md)。

## 首轮调查（#474）

2026-11-02 的 Windows 运行使用本地客户端语料，共 7,120 文件 / 91,205,771 字节，内容身份为
`a484ae33324917c2791c019449ed62b557036fb113e757ba6f0acc79b8bffaf5`。
一次完整的基线精确查询总计 7,450 ms：受保护路径校验/打开占 4,918 ms，相对元数据占 933 ms，
绝对元数据占 765 ms，glob 过滤占 45 ms。这表明后续应单独评估可安全复用的路径上下文；
每请求仅准备一次 glob 不会消除主要文件系统工作。

该机器同时运行了其它验证工作。相同二进制的控制组在无命中查询触及 30 秒截止时间时，也返回
了不同的局部结果。应保留这些失败，而非将不同工作量对比为提速。首次与预热样本、worker 摘要
及新旧实现对比附在 [issue #474](https://github.com/T-Auto/dsh-ops/issues/474) 所链接的修复 PR 中。
此语料不同于报告者此前的 3,155 文件语料，当前证据不构成整体提速结论。
