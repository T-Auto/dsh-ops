# 私有 Shell 通道共享溢写

English: [Shared spill for private shell channels](private-channel-spill.md)

此 #872 内部切片让每次持久 Shell 命令的 stdout/stderr 复用
[原生原始输出溢写基础](原生原始输出溢写基础.md)，不新增第二套写入器、存储、账本、
清理服务或宿主调度器。公共工具与运行时固定版本不变；POSIX 所有权范围仍不受支持。

`Driver::prepare_with_spill(Some(store))` 接受内核所有者持有的 `SpillStore` 克隆；
同一实例也可以传给任务的 `Range::enable_spill`。普通 `Driver::prepare()` 不溢写。
命令、启动及完成回执管道继续使用小型有界前缀缓冲区。仅两个输出通道选择溢写，保留
既有有界前缀，并通过共享存储提供上限 64 MiB 的完整原始文件。

既有四实例管道上限、Job 对端检查、精确前缀选择及连接就绪屏障继续生效。空的元数据
打开不会启动捕获、公布溢写或标记输出 EOF。只有通过前缀认证的实际写入者拥有
`Output`。`OUT:<id>` / `ERR:<id>` 在字节计数前剥离，绝不进入文件。包括无效 UTF-8
在内的二进制输出在文件中保持原始字节，即使小型显示前缀使用替换字符。

`ChannelSnapshot` 新增与任务捕获相同的 `spill` 和 `spill_error` 元数据。
`writer_closed` 表示认证管道的原始 EOF；直到捕获封存完成，`writer_eof` 才变为 true。
`storage_pending` 表示实际读取线程工作，而非根据静默时段猜测完成。这些事实让 Driver
区分待完成写入/封存与被保留的描述符。已知存储工作会刷新既有短暂的描述符收尾宽限，
独立请求期限仍生效。成功依然要求私有完成回执、物理输出完成和精确保留的启动进程身份。

文件系统工作留在既有通道读取线程，从不持有快照或协调锁。`Channel::close_until`
取消该通道的文件及管道操作并加入所有读取线程。如果超时或输出中毒，会保留线程并设置
`cleanup_unconfirmed`。`Call::cleanup_unconfirmed` 汇总该状态；
`Driver::cleanup_unconfirmed` 覆盖其控制通道及进程范围资源。调用方必须停止准入，
并在丢弃已中毒所有者之前独立关闭控制传输，让公共宿主终止受管理内核。`Drop` 不会
分离仍持有 I/O 的线程。仅 Shell 进程范围停止成功，不能证明另行拥有的单次捕获已加入。
生产会话失败路径现在检查这两个所有者，并在可能丢弃它们之前调用 Manager 的致命回调。
首先关闭准入；传输失联后不承诺终态回执。确定性的受阻读取线程夹具验证了这一顺序，
并在恢复旧调用方行为时失败。

仓库 `shell_driver --spill` 示例实际验证此边界。真实探针验证精确内存边界、三个
sandbox 模式下完整的 1 MiB 二进制 stdout/stderr、保留 cwd/环境/函数/选项、多个 Shell
共用一个存储、既有账本保留、兄弟 Shell 继续可用以及没有所属进程残留。经评审的本地
Niubash 回移修复版本还将外部命令作为后台任务并使用 `wait`。stock CI 调用明确仅验证
前台命令，不证明 stock 异步输出合格，也不暗中缩小最终会话功能契约。

三个确定性原生测试覆盖空元数据打开与实际写入者、实时完整前缀与帧剥离、写入停滞时
快照仍可响应且所有权保持中毒，以及管道已 EOF 但封存仍待完成。溢写创建、上限、写入、
关闭和不可逆中毒仍由共享基础实现并测试。为公共会话启用此可选存储前，还须完成生产
会话元数据传输、结算账本移交及合格运行时启用。
