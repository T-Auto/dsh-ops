# 文件读写契约

English: [File read and mutation contracts](file-contracts.md).

下表描述当前契约及有意保留的工具差异。Native 是有预算的显示文本；PTC 使用 `Outcome.data` 中的 canonical 数据。不要把带行号的 Native 显示反向解析成文件字节。revision 是完整已读取字节（包括 BOM 与换行）的 SHA-256 小写十六进制值。

| 操作 | 前置条件 | canonical 事实与回执 |
| --- | --- | --- |
| `inspect_local_file` | 已存在且可读取的文件，有界行/字节视图 | 顶层 `revision`、`bytes`、`lineCount`；`items` 为物理行。`complete`、`nextOffset`、`truncatedInLine` 描述返回范围。 |
| `read_files` | 1–32 个明确范围，共用总输出预算 | 每个文件项有自己的 revision、覆盖信息与行或错误；不能只看外层状态。 |
| `write_file` | `expectedRevision` 必填：覆盖传已观察 SHA-256，新建传字面字符串 `"absent"`；父目录须存在 | 完成回执的 `revision` 是写后值。省略、`null`、空字符串都不是有效 revision。`"absent"` 不会覆盖已有文件。 |
| `edit_file` | 已有 UTF-8 文件，观察到的 `expectedRevision`，1–100 个非空且符合唯一性要求的 `oldText` 替换 | `revisionBefore` 是读取的写前值，`revision` 是写后值。过期 revision 返回 `REVISION_CONFLICT` 且无效果。未选中的 BOM、换行与文件尾字节保持不变。 |
| `replace` | 字面 pattern/replacement、有界范围与匹配上限，可预览 | 每项 `revision` 为写前值，`revisionAfter` 为计划写后值。实际执行标明 `completed`、`error` 或 `pending`。工具内部扫描并在每个文件发布前比较自己的读取，不接收调用者的 expected revision。 |

`write_file` 与 `edit_file` 的整个请求最多 **2 MiB**，包含 `content` 或 `edits` 及协议封装。更大的变更应拆成多次带 revision 校验的调用；单独的 32 MiB 单文件内容上限并不是实际请求预算。

`stat`、`copy`、`move` 与 `remove` 以流式 SHA-256 计算 revision，不再整读文件，因此可处理超过 32 MiB 的文件。hex 检查会在不缓冲完整内容的情况下流式计算整文件事实，随后只定位并缓冲请求窗口。需要完整内容的文本检查、`diff` 与写入缓冲仍保留各自明确的内容预算。

在不支持命名流或 ACL 的 Windows 卷上，写入会保留可用的基本元数据并返回 `metadataWarnings`，不再返回 `METADATA_UNSUPPORTED`。Windows 上真实存在但不受支持的源元数据（例如 NTFS 备用数据流）仍会闭锁拒绝。

`replace` 不绑定之前 `inspect_local_file` 的读取结果。单文件变更必须依赖该次读取时使用 `edit_file`。replace 预览不会预留文件，执行时重新扫描。`changed` 是已应用字面替换次数，不是文件数。预览带 `dryRun: true`，仅有计划 hash 不能证明已经写入。目录替换遇到读取权限拒绝时会记录 `skippedPaths`，返回 `complete: false` 与 `truncated: true`，并继续处理其他合格文件；普通的二进制文件跳过本身不会使结果不完整。更新锁、暂存与发布阶段的权限拒绝仍使调用失败，共享冲突及其他 IO 故障也保留结构化错误，不会改记为跳过。

## 目录发现与不完整扫描

`glob` 新增与 `outputMode` 独立的 `kind: "file" | "directory" | "all"`，默认仍为 `file`。
`{ pattern: ["*"], kind: "directory" }` 列出直属子目录（包括空目录）；`all` 混合返回文件和目录。
`paths` 返回字符串；`details` 返回 `{ path, bytes, modified }`，在 `directory`/`all` 查询中附带 `kind`。
目录字节数只是文件系统元数据，不是递归大小。隐藏项、依赖/构建目录、符号链接、junction 和其他 reparse
point 仍排除。目录查询使用有预算的 no-follow 遍历；仅文件索引不能证明空目录存在。

不完整扫描保留 `scannedFiles`、`matchedObserved`、`skipReasons` 与 `scanComplete: false`。
已观察匹配仅为下界，不提供稳定续扫游标，也不声称全量总数。`nextAction` 建议把 `path` 收窄到更小的
可读子目录并重新查询，并在可用时附最多两个缺口样例（稳定错误码与路径）。非 UTF-8 名称以所属目录作为
样例。策略性排除仍与扫描缺口分开；完整扫描保留原有分页与 continuation 校验。

## 同一轮 PTC：读取、推导、编辑

按 [PTC 按需加载](PTC按需加载.md) 在执行轮前加载所需绑定。`ops_load_sdk` 成功且 `nextTurn: true` 不代表同一个 `run_code` 可以立即调用此前缺失的绑定。`OpsSdk` 描述完整类型目录，不保证当前 Agent 已加载所有绑定。

```ts
const read = await tools.ops_inspect_local_file({ path: "settings.txt" });
if (read.status !== "completed") return read;
const row = read.data.items?.find(item => item.line === 2);
if (!read.data.revision || !row?.text || row.truncatedInLine) {
  return { action: "先读取完整的目标编辑范围，再选择待修改文本。" };
}
return await tools.ops_edit_file({
  path: "settings.txt",
  expectedRevision: read.data.revision,
  edits: [{ oldText: row.text, newText: row.text.replace("setting=old", "setting=new") }]
});
```

示例把实际读取文本与 revision 直接交给 CAS，不猜测缺失行、不拼接带编号的显示，也不归一化换行。调用者仍须选择唯一且符合意图的 `oldText`；重复行存在歧义时拒绝。`partial` 保留数据与只读续读指导，不允许将未读或被截断内容视为空。完整范围可以小于整份文件，需判断已见范围是否足够支撑当前编辑。

新建明确传入字符串：

```ts
return await tools.ops_write_file({
  path: "new.txt", content: "hello\n", expectedRevision: "absent"
});
```

`"absent"` 不是「省略字段」的提示。读取与编辑之间若有外部写入，会发生冲突；应重新读取并重新判断编辑意图，不能只更新 expected revision 就盲目重试原编辑。

## 部分变更与错误

多文件替换是一系列文件级原子发布，不是跨文件事务。A 成功、B 失败时，`Outcome.data` 保留 A 的完成回执、B 的错误以及后续待处理文件。`failed` 与 `pending` 计文件数，`changed` 计失败前确认的替换次数。完成回执的写后 hash 对应已发布字节；错误或待处理项的写后 hash 仍只是计划。

先检查 `error.effectState`：`none` 为无效果，`applied` 表示此前已有变更，`unknown` 即使保留已知回执也仍须只读核验。此类错误不提供自动写入续传。应检查回执与当前文件状态，不能盲目重放整个替换。错误码不能覆盖副作用不确定性；元数据警告与发布成功分开表达。

生成的声明保留这些不同的回执形状并要求状态收窄，其来源是同一能力目录。数量边界、SHA-256 有效性与空字符串仍由运行时校验。回归覆盖真实 `run_code` 同轮读改、外部写入 CAS 冲突、混合/部分读取、Windows 后续文件替换拒绝、Native 回执显示和正负 SDK 编译。此项不增加隐式重试或变更语义的便捷 helper。
