# 常驻任务输出与保留

[English](resident-task-spill.md)

此 #872 切片将共享[原始输出溢写基础](原生原始输出溢写基础.md)接入原生任务队列和现有
宿主输出/保留契约。Windows 内核在就绪前配置一个仅分配内存的 `SpillStore`，声明
`task-v1` 与 `task-spill-v1`。仅有 `task-v1` 仍不足以切换生产 fresh 后端。
本切片不改变已发布 fresh executor，不启用持久会话，也不认定任何 shell runtime 合格。

固定任务 worker 将共享 store 克隆到各自独立拥有的进程范围。每条流仍保留最新
64,000 个原始字节。溢写目录由现有 reader 延迟初始化；初始化失败时保留有界尾部，
不会使内核启动失败。最多 64 MiB 的完整流通过现有相关输出回执中的 `spillPath`、
`spillOrigin: ops-native-v1`、`spillPid`、`spillSealed` 和独立 `spillError` 提供。
实时路径覆盖该回执的全部已观测前缀。超限或存储失败撤回路径，不会把部分文件声称为完整输出。

`task.read` 仍然有界且不消耗其他 reader。宿主将原生 PID 与实际内核核对，为 Jobs
保留独立实时字节游标。终态读取必须与原生流总量一致；返回的 spill 必须已经封存。
公开结果仍使用现有有界 `ShellStream` 格式，仅在原生仍确认完整时提供 spill 路径。
不增加宿主输出 writer。

两个终态读取完成并确认回收后，只将已到 EOF、无原始捕获错误、已封存的原生流记录到
既有账本，携带精确内核 PID、原始字节总数和捕获的 owner Session ID。命令失败不会
使另一条完整流失效；原始捕获错误或回收未知不能建立终态所有权。实时路径不会进入账本。
每条命令只通知共享保留调度器一次；账本或调度器失败不改变已经执行的结果。原宿主
subprocess 路径使用相同结算 helper，保持其旧 origin 和输出契约。

任务完成使用有界 reader join。输出回收无法确认时，在发布失败前封闭 owner，保留
中毒范围并关闭独立控制端点，随后由公开宿主终止所属内核。中毒之后迟到输出不能恢复
EOF、完整路径或独立回收确认。普通定向取消仍只 join 自己的范围；完整已观测输出到达
EOF 后可以封存，不会仅因某条命令取消就终止无关 owner。

Windows CI 的[任务 spill 探针](../bench/probes/probe-872-task-spill.mjs)使用真实公开
Jobs registry、sandbox 与 resident provider，验证：内存边界；经既有 file bridge
完整恢复 stdout/stderr；workspace-write 写入拒绝；实时 Jobs 元数据与终态账本的区别；
超限撤回；取消任务封存；既有保留流程；以及内核硬崩溃后无重放的回收。它记录 worker
哈希、confinement、进程身份和清理，保留失败样本。这是内部装配，并不替代生产 fresh
权限桥接或独立的官方 Jobs 工具/发布验收。

```console
cargo build --locked --manifest-path native/Cargo.toml --bin dsh-ops-worker
npm run build
node test/run.mjs resident-task-spill-settlement resident-task-execution
node bench/probes/probe-872-task-spill.mjs native/target/debug/dsh-ops-worker.exe task-spill-report.json
```
