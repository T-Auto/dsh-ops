## 已实现的能力

包中有七个稳定组件行：shell、file、PTC、discovery、panel、TUI、官方工具替换。新配置默认开启 file/PTC/discovery；三个平台默认开启 shell；panel/TUI/替换默认关闭。已有带名称覆盖、显式开关与配置在重启后保留。启用新 panel 行即采集；旧配置显式 capture:false 仍不采集。关闭时物理停止排队文件操作。

Native 默认只发布 read_files、discover_tools，以及可用的 Bash（Windows 为固定载荷，POSIX 为发行版 bash）。高级工具仅在所属 agent 的下一次供应商请求中激活。PTC SDK 目录共18个 API：15个文件/文档工具，加 batch、result、load_sdk。共享目录另含 bash 与 discover_tools，共20项。目录成员并不等于启动常驻；SDK 与 Native 分别提供类型化数据和文本，实际发布与每次调用仍受作用域、允许池和权限约束。

Rust worker 仍按调用启动，每次重新检查权限。Native 文本有界并可逆转义行内容，PTC 返回类型化 Outcome。结果引用保留源扫描、分页与捕获完整性，不授予文件权限。相同内容重读去重要求确切的供应商输入证据，只有消息历史不足以证明可省略正文；见[上下文读取去重](上下文读取去重.md)。

全部插件源码均为严格 TypeScript/TSX；构建拒绝 src 下的 JavaScript，输出到 lib，保持已发布 .js 路径。仓库脚本和测试可继续使用 JavaScript；lib/runtime 是构建产物。请按[源码构建步骤](贡献指南.md)安装，不直接使用未构建 Git 检出。

## 文档范围

| 工具 | 支持范围 | 主要边界与排除项 |
| --- | --- | --- |
| read_table | CSV/TSV 字符串单元格；严格 UTF-8 或 BOM 一致的 UTF-16LE/BE | 输入32MiB、100000数据行、每记录1MiB、1024列、30秒。不支持 XLS/XLSX、公式计算或类型推断。 |
| read_docx | DOCX 主体段落，保留表格坐标 | 归档32MiB、主 XML8MiB、每段1MiB、100000段、30秒。不支持二进制 DOC、宏、加密/ZIP64、外部抓取或落盘解压；不含排版、页眉页脚、注释脚注及元数据。 |
| read_pdf | PDF1.3–1.7 经典 xref 文本层；标准 Helvetica/Courier/Times Type1 与 Standard/WinAnsi | 输入16MiB、32页、每页/流1MiB、解码与处理流各16MiB、30秒。不支持 OCR、图片、通用排版、表单、自定义/嵌入/CID 字体、ToUnicode、加密、增量更新或对象/xref流。 |

这些是有界读取器，并非通用 Office/PDF 转换器。后续不支持内容只保留此前完整记录，返回错误和下一步；offset 不能跳过物理扫描缺口。仅稳定完整扫描提供 total/revision；展示页或缓存页完整不代表源内容完整。详见[原生内核文档契约](原生内核.md)。

## 操作者变更

Bash 是主包的 Windows 可选 npm 载荷（安装时自动拉取）；PowerShell 由宿主管理，不是 npm 载荷。受管理 Bash 安装/删除、Git Bash 选择仍是显式操作与修复路径。Windows 受限执行仍是部分约束，且要求兼容的固定 MSYS 运行时；审批不能补足缺少的隔离。宿主 PowerShell 升级先预览标准安装，需显式执行、重启 DSH，并检查自定义 pwshPath。

内置行表单通过宿主持久化严格校验后的配置。可选浏览器页面需要显式执行离线 settings-profile 迁移，因为固定宿主仅从裸包名承载行加载浏览器 facet。默认旧文件行仍受支持；迁移保留七行 ID/配置、先备份并精确验证合成结果。关闭承载行卸载全部自定义页面，通过宿主行开关恢复；见[配置参考](配置参考.md)。

| 步骤 | 已实现行为与边界 | 证据 / 待决事项 |
| --- | --- | --- |
| 1 — 构建 | src → lib 与资源构建，保持发布路径；Git 源码安装须先构建。 | build 与打包门禁；临时 JavaScript 迁移许可已在第 16 步移除。 |
| 2 — 契约 | 统一能力目录、Outcome、错误/重试、覆盖与引用类型。 | kernel-types、kernel-errors 和 schema；Native 文本与 PTC 数据保持分离。 |
| 3 — Native 投影 | 可逆转义行号文本、短回执与不完整提示；转义后展示上限 64 KiB。 | native-projection、native-line-encoding、native-ranges；不保证普遍百分比节省。 |
| 4 — Worker | workspace crates 与 v1 有界单次请求，每次重检权限。 | Cargo workspace 与协议回归；持久 IPC 仍待独立安全评审。 |
| 5 — 读写/搜索 | 最多 32 个独立读取范围、单文件原子多段编辑、如实搜索缺口与续取。 | file-batching-worker 与搜索回归；不提供跨文件原子编辑，扫描缺口后不声称全量总数。 |
| 6 — 引用/预算 | 每结果 10 MiB、每会话 100 MiB；两活动/八等待、worker 30 秒上限；审计独立。 | result-references/spill/lifecycle、call-budget、native-result；权限不足清理可能留下已失效临时块。 |

## 堆叠评审与 staging 集成

当前 PR 为限制单次差异而使用前置分支作为评审基线，并非全部直接指向 release/0.4.0。例如 [1/16](https://github.com/T-Auto/dsh-ops/pull/264) 指向 staging，[2/16](https://github.com/T-Auto/dsh-ops/pull/265) 指向工具链分支，[14b/16](https://github.com/T-Auto/dsh-ops/pull/283) 指向 14a 设置分支；15a–d 与 16a 继续以前一切片为基线。PR 编号不是依赖顺序：第 13 部分较早创建，当前基线实际是第 12 部分。

维护者应按计划/依赖顺序将前置切片评审并集成到 release/0.4.0：1；2→3 与 4a→4b；随后 5a→5b、6a→6b→6c→6d、7–13、14a→14b、15a→15b→15c→15d、16a→16b→16c。前置已进入 staging 后，将下一评审调整到合适的当前基线，确认 diff 仅包含目标切片，集成有变化则重新运行必需 CI。不能仅因旧分支仍是评审基线，就把后续工作合入过时前置分支；保持共享历史，不由本次工作代替维护者合并 PR。

全部功能门禁与已批准验收标准通过后，维护者才应评审 release/0.4.0 → main 的最终发布 PR。操作者已明确批准 OPS 0.3.x 为 BM-01 权威基线、官方读取另列对照，以及文件/发现 ≤400 token 的 BM-03 范围并保留 Bash 启动常驻。固定无损工作负载、完整默认工具清单、schema 契约和权限检查保持不变。下文保留之前完整范围失败，不将它悄然重分类。版本提升、PR ready 或单独功能 CI 通过均不授权打 tag/发布。
