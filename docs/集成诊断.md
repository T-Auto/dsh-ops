# OPS 集成诊断

## 执行计时（#872，切片 A）

向 `ops_bash` 传入 `includeDiagnostics: true`，默认关闭。前台、后台、转后台及拒绝结果
均可带 `executionTiming`；执行器结算结果另带 `diagnostics.timing`。每份都是独立快照，
不存在全局遥测缓存。

| 字段 | 实际边界 |
| --- | --- |
| `wallMs` | OPS 工具入口到返回边界的单调时钟耗时；不含入口之前的宿主调度、序列化和调用方收包，完整调用须外层计时 |
| `admission` | 参数校验、工作目录解析 |
| `policy` | 会话权限、审批、环境收集，包含人工审批等待 |
| `queue` | 宿主 job 准入到其执行回调启动；无 job 时未观测 |
| `prepare` | 运行时准备、执行前权限复核、sandbox confinement |
| `launch` | 同步 `subprocess.spawn` 调用，不代表目标进程已经启动 |
| `hostWait` | 等待宿主 `done`，包含 runner 和输出处理，不是纯命令 CPU 时间 |
| `outputFinalize` | 保留输出读取、spill 记账、执行器结果投影 |
| `resultReturn` | 工具结果投影到返回宿主之前 |

阶段含相对同一起点的 `startMs`、保留小数的 `durationMs` 和状态。未观测为
`not-observed` 与 null，不能伪造为零；`running` 是尚未完成的区间。后台与转后台结果
只是交接快照，不代表任务结束。`diagnostics.durationMs` 保留执行器局部含义，不能当作
完整工具延迟。执行器快照早于宿主结果投影；前台总耗时应看外层 `executionTiming`。

当前宿主公开的 collect 模式 API 没有 first-byte 事件和独立 target-exit 通知，`done`
也不等于整棵进程树结算。因此 `unavailable` 明示三个不可观测项，`hostDoneMs` 只记录
成功观察到 `done` 的时间。不为凑指标轮询输出或额外调用 `waitForExit`，避免改变生命周期。
每次调用最多保留固定数量的阶段记录；不新增进程、计时器、监听器、日志或磁盘产物，
不把命令正文、环境变量或路径写进计时快照。

仓库辅助函数 `bench/probes/execution-timing.mjs` 的 `sampleExecution` 接收真实调用的
`invoke({ signal })`、结果校验 `validate(result)` 和环境元数据，调用示例见
[英文说明](diagnostics.md#execution-timing-issue-872-slice-a)。必须绑定实际挂载的
Native/PTC 调用入口，等待完整结果并传递取消，不能用裸 spawn 或 mock 代替性能证据。
元数据必填 system、host、plugin、runtime、permission、projection、workload、storage、cache。

该函数不自动安装或启动环境、不写文件，串行采样；默认 200 次热态、10 次预热，最多
10,000 次热态。首调用、预热、失败样本均保留，报告 p50/p95/p99、错误率与各阶段有效
样本数。首调用不等于已证明冷缓存；阶段分位数仅统计已结束的观测。资源数据仅属于
采样器进程，子进程 CPU/RSS、句柄、临时磁盘明确未知，最终性能门禁须另采集。
每个负载都须校验输出，退出码为零不代表语义等价。

计时不构成 Windows 胜过 Linux 的证据。最终对照仍需交错多轮、完整负载/权限/投影矩阵、
WSL ext4，以及等价 containment 与结果保留。宿主后端继续默认启用，摇篮需显式选择。

## Windows 摇篮与常驻执行器

在 shell 行或相应内置模式配置节（例如 `ops-ptc`）设置 `executionBackend: cradle`。
默认 `host`，显式选择摇篮后不静默回退。沿用 `build:ptc` 构建与 stage；监督器是原有
provenance 校验 worker 二进制的 `--cradle` 入口，不增加下载运行时。非 Windows 明确
拒绝该后端，继续使用原宿主执行器。

所有权以 Cordis 内核 root 为键，不按 PID、home 或工作区共享。同一内核的组件租约共享
惰性监督器；每代有随机 128-bit nonce、私有继承 stdin/stdout 和已打开父进程句柄。
不建立公开端点、TCP、进程名扫描、每命令看门狗或磁盘握手文件。控制连接关闭或父句柄
示意退出时，监督器退出并通过 kill-on-close 收敛所有 Job。

监督器持有任务 Job、目标句柄、两路输出读取与结算。常驻调度线程仅验证启动数据，不持有
Job；单请求 panic 被隔离，不重放已执行工作。任务先 accepted/prepared，再由宿主复核
当前权限并 commit。每任务使用显式 stdio 继承白名单以及 suspended-create → assign →
resume；Job 或 nested Job 约束失败即拒绝，不开 breakaway。Job 无名、不继承、kill-on-close。
每命令仍为 fresh shell，独立 cwd/env/options/trap/函数与 EOF stdin，不偷偷持久化 shell
状态。固定文件 worker 保留逐请求权限边界，不变成跨会话高权限池。

协议有严格递增 request id，accepted、prepared、started、targetExit、settled、ack
边界。已提交请求断连不重放，效果报告未知。必须目标退出、Job active-process-zero、
两路输出 drain 与结果交接完成后才结束宿主任务；关闭输出 fd 的后台后代也仍属于活任务。
查询与取消继续使用 DSH `job_output`/`job_kill`，不另建宿主不可见的后台任务表。
Windows 非 console 任务没有可靠协作中断，因此明确取消时直接 TerminateJobObject。
原执行器继续拥有 deadline，转后台只取消该 deadline；会话销毁取消所属租约的任务，
最后一个组件租约释放监督器并提供有界的精确子进程退出升级。

Running → Idle → Draining → Exited 使用 `Instant`。仅在所有任务结果 ack 后任务表为空
才启动 300 秒空闲计时；排队、运行、后台、输出 drain 都计为忙碌，静默数小时任务不回收。
准入与退出由监督器事件循环串行处理；退休竞态明确返回连接失败，不透明重提命令。
下一次独立调用建立新一代，调度线程随监督器退休。

资源上限：32 个准入任务、1 MiB 帧、256 个输出队列帧（每帧 8 KiB 原始字节，hex 编码
且不解释命令输出）、宿主 2 MiB 待发送控制数据、每流 64,000-byte 尾部、64 MiB spill、
每代 256 MiB 保留 spill 预留。写磁盘期间暂停管道读取传递背压；磁盘失败/配额耗尽撤销
完整 spill 声明，保留有界 tail 与丢失标志。仅溢出时建立兼容既有 ledger 的私有文件，
由原 retention 策略回收；退出删除空目录，不提前删用户结果。Job 使用 completion port，
输出阻塞读，父进程句柄阻塞等待，不轮询进程表。15 秒启动握手期限不是任务寿命或心跳。

所有调用仍经过原参数校验、sandboxPolicy.resolve、审批、sandbox.confine、权限复核及
宿主环境凭据清理。实际执行 confinement 的 argv，不支持的宿主来源/清理契约明确拒绝，
不替换为裸命令。原生平台边界、协议、租约、输出与 DSH 适配分模块维护；Native/PTC
仍从既有工具入口发布与审计。

代码交付不等于验收。多内核、nested Job、父/监督器崩溃、空闲竞态、取消风暴、撤权、
磁盘/管道压力、真实 Web/Desktop 和 Windows/Linux 性能矩阵仍待操作者执行，
不声称已有运行测试或性能结果。

## 集成状态

[English](diagnostics.md) | 中文

`dsh-ops/integration` 会在对应作用域发布只读的 `ops_status` 诊断工具。它报告当前预设、
可见工具、接入状态、外部提供者状态和可操作错误码；不执行文件/Shell/第三方动作，也不会
激活发现能力。

按需查询也返回 `runtimeVersion`，已知时附带 `runtimeVersionSource`。适配层调用宿主
`pluginPackages.resolution` 中 installation 作用域选定的 `app-boot` 包的
`getDshRuntimeVersion()`，保留预发布与构建标识。缺少权威来源或来源不唯一时返回 `unknown`，
不从 OPS 依赖、npm、可执行文件元数据或继承的 `DSH_VERSION` 推测当前版本。提示词、SDK
声明及普通工具结果不会因此增加版本、插件列表或配置路径。未提供该安装解析表的宿主，需要
宿主自有的版本服务才能通过此适配层报告已知版本。

状态含义：

- `not-selected`：当前 Agent 没有显式 OPS 接入，也没有启用的内置模式。
- `ready`：接入已挂载，声明的宿主与运行时检查通过。
- `degraded`：已选择接入，但宿主服务、运行时、Shell、展示模式或发布不完整；不等于用户未选择。
- 外部 `available`：已允许且提供者存活，但按需加载；`pending`：将在下一模型步骤生效；
  `active`：已在当前作用域可见；`disabled` 与 `unavailable` 表示明确原因。

`PRESENTATION_MISMATCH` 必须检查实际 assemble 结果：PTC 要求 `run_code` 和非空
`tools:ptc-only` 段，不能用预设名或提示词建议推断。`PUBLICATION_UNAVAILABLE` 应先检查
接入生命周期、作用域和注册错误，再考虑权限。若官方工具已隐藏但对应 OPS 工具不可见，
这是替换控制器缺陷，不能要求用户重试。
