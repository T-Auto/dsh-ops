# OPS-PTC 四本账成本分账（#991）

## 为什么要有这本账

OPS-PTC 计量常见的错误是结构性的：把 `tools:sdk` 在已包含它的 system 总量上再加一遍造成双计；把 Native 的工具 schema 混进 PTC 测量；或者放错 dsh-ops 引导的位置：一次性教学随被接受的工具结果走同一步 `additionalContexts`、从不记为历史，history 账只记录形状提醒，两者都不是系统提示。V1（#990，`test/lib/ptc-entry.mjs`）已经保证被测组真正进入 OPS-PTC；本套件在那条入口上补齐字节分账，四本账永远不互相混同。

`test/ptc-cost-accounts.test.mjs` 用 `bootEntryGroup` 启动一个隔离组，先用 `enterPtc` 证明路由，再走一段脚本化场景——首次教学、一个引来 plan 提醒的薄程序、一次合规的 `ops_load_sdk` 加载（`glob`/`grep`/`read_files`）、以及同配置重复请求——每本账都以原始 UTF-8 字节加各项名字清单输出。

## 四本账

下表读数取自 commit `205cb94`、插件 0.5.5、宿主 0.2.2-rc.1、linux-x64、staged worker sha256 `2b5f988d…`、预设 `ops-ptc`、常驻 + 动态 + 批量教学开启、官方 read/glob/grep 已挂载的一次运行。绝对字节只在同一配置内可比。history 行记录 #929 之后的构成：一次性教学是同一步上下文，不计入该账。

| 账目 | 首次请求（仅常驻） | 加载后 | 重复 |
| --- | --- | --- | --- |
| system（投递的渲染提示） | 12,782 B | 37,892 B | 37,892 B |
| ——其中 `tools:sdk` | 11,739 B | 36,849 B | 36,849 B |
| wire（外层工具 schema） | 2,500 B | 2,500 B | 2,500 B |
| history（dsh-ops 提醒） | — | + 提醒:plan 284 B | 不变 |

- **system** 是投递出去的渲染提示，按 provider 请求实际携带的口径计字节；套件断言每个配置点的请求 system 消息与空闲快照的渲染结果一致。首次请求的逐项清单：`harness:identity` 48、`tools:ptc-only` 159、`tool:read` 130、`tool:write` 92、`tool:edit` 83、`tool:glob` 75、`tool:grep` 133、`dsh-ops:repository-tooling:mode-ptc` 307、`tools:sdk` 11,739。
- **sdk** 是 system 内唯一的一个 `tools:sdk` 小节——严格子集，绝不是另立账目。归一化规则由断言钉死：system = 逐小节字节按 `\n\n` 连接，即 12,766 + 8 个连接 × 2 B = 12,782，可用上表清单手工复核。
- **wire** 是请求外层工具 schema 的 `JSON.stringify`——本场景恒为 `run_code` 一项，每个请求字节一致，且等于空闲装配的 wire。
- **history** 是套件按每次请求实际投递的消息、针对 contributor `batching-guidance` 记录的 dsh-ops 引导：薄程序引来的 plan 提醒（一次，284 B）。一次性教学不出现在这里：它随首个被接受的根 `run_code` 结果走同一步 `additionalContexts`（contributor `batching-guidance:lesson`），从不记为 user 历史，因此该账不含教学字节；完整教学正文为 8,729 B。套件断言两者都不进 system 账——提醒之后的 system sha 与基线相同。

## 必须成立的算术

加载 `glob`/`grep`/`read_files` 就是那个手算样例：steady 与 loaded 两个快照之间，除 `tools:sdk` 外每一小节字节级不变，system 增量 === SDK 小节增量（+25,110 B）——这个变更在 system 里只出现一次，SDK 子集绝不双计。同一 fixture 同一代码的两个全新组必须逐字节一致（sha 相等）；同一会话内同配置重复请求必须字节相同。

## SDK 名称与真实官方 schema 的对比

场景在行挂载之前先装上宿主自己的官方文件工具插件（与预算套件相同的 `FsTools`/`SearchTools`），因为 SDK 名称只有对着被替代的 schema 才有意义。官方 schema 按 name+description+parameters 的 JSON 计为：`read` 438 B、`glob` 750 B、`grep` 702 B。

在本基线上，正式行并**不会**把这些官方绑定从 PTC SDK 里移除——`read`、`glob`、`grep`、`write`、`edit` 仍与 `ops_inspect_local_file`、`ops_load_sdk` 并列声明（PTC 隐藏修复是 open PR #961；#978 的对照读数取自其 head，不是这里）。套件有意钉住这个基线：#961 合入后该断言转红，账目必须重新计量并更新文档。缺少官方提供方时，套件把对比标记为**不可测**并列出缺席名称，绝不静默放行。

## 刻意不测的部分

- 夹具从不发出真实模型请求：provider 是脚本化的，每条打印记录都带 `provider: "scripted"`、`networkModelRequests: 0`。
- 不测 token、缓存用量或费用：字节不是 token，bytes/4 不是实测 token 数。token 归 provider 输出（V5 范围）。
- worker 缺失时整套件可见地 skip——skip 不是 pass。
- 绝对字节不跨版本、不跨组相减；不承诺固定百分比。

## 复现

```
npm run build
npm run build:ptc
DSH_OPS_WORKER_BIN=$PWD/runtime/linux-x64/dsh-ops-worker node test/run.mjs ptc-cost-accounts
```

套件每个快照打印一行含四本账与 scripted/0 标注的 JSON；设 `DSH_OPS_PTC_COST_REPORT=<file>` 可得逐项完整证据。`node test/run.mjs ptc-cost` 会把本套件与共享过滤器的声明成本套件一起运行。
