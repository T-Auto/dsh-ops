# 磁盘与缓存

[English](disk-and-cache.md) | 中文

OPS 可能创建的每一类磁盘资源都有明确归属、保留类别与默认动作；`dsh-ops disk status` 以只读方式报告它们。该报告**不删除任何东西**，本页也没有任何“将来一定自动淘汰”的承诺：回收必须有归属证据，绝不按目录名或修改时间猜测。

## 运行报告

```console
dsh-ops disk status                 # 人类可读表格
dsh-ops disk status --json          # 稳定机器格式（dsh-ops/disk-status@1）
dsh-ops disk status --config row.json
```

`--config` 读取 JSON 文件，形状与该行配置一致，例如
`{"disk":{"status":{"includeRepository":true,"maxEntries":100}}}`。它与 `ladder --config` 同规则：插件拒绝的键会先在这里失败。

JSON 报告包含 `schema`、`generatedAt`、`platform`、`home`、`tempRoot`、`workspace`、`config`、`resources`、`totals` 与 `notes`；每个资源行包含 `id`、`name`、`category`、`owner`、`action`、`cleanupEntry`、`description`、`paths`、`samples`、`bytes`、`files`、`count`、`ageMs`、`reclaimableBytes`、`reclaimBlocked`、`truncated`、`skippedCount` 与 `skipped`。

字节数是普通文件的表观大小：符号链接从不跟随、只记为跳过；无权限条目与根外目标降级为跳过而不会让报告失败；遍历在 `disk.status.maxEntries` 处停止。嵌套行（`R3`、`R4`、`R11`）计入父行并从 `totals` 排除，避免重复计算。

## 类别与默认动作

| 类别 | 含义 | 默认动作 |
| --- | --- | --- |
| `renewable` | 可重建或可丢弃的 OPS 状态 | `report-only`：只有带归属证据的清理入口可回收 |
| `diagnostic` | 面板采集、批处理审计、ACL 备份收据 | `never-touch`：这是“发生过什么”的唯一记录 |
| `user-artifact` | 存放用户/模型工作的会话临时目录 | `never-touch`：插件永不删除 |
| `host-owned` | 宿主 subprocess 的溢出目录 | `report-only`：OPS 不清理其它 provider |

`report-only` 表示行内用 `reclaimBlocked` 说明为何保留；`explicit-command` 表示只有点名的运维命令可以回收；`never-touch` 表示没有任何 OPS 入口会删除它。

## 资源清单

| Id | 资源 | 位置（模式） | 类别 | 动作 |
| --- | --- | --- | --- | --- |
| R1 | Niubash 执行副本 | `<OS temp>/dsh-ops-niu-exec-*` | renewable | report-only |
| R2 | 结果缓存根 | `<OS temp>/dsh-ops-results-*` | renewable | report-only |
| R3 | 结果快照（嵌套于 R2） | `<root>/s-*` | renewable | report-only |
| R4 | 批处理审计库（嵌套于 R2） | `<root>/.dsh-ops` | diagnostic | never-touch |
| R5 | 会话临时目录 | `<OS temp>/dsh-ops-session-*` | user-artifact | never-touch |
| R6 | 面板采集 | `<workspace>/.dsh-ops/panel` | diagnostic | never-touch |
| R7 | 宿主 subprocess 溢出 | `<OS temp>/dsh-subprocess-*` | host-owned | report-only |
| R8 | 受限 Bash 代 | `<DSH_HOME>/dsh-ops/bash-ipc` | renewable | explicit-command |
| R9 | 已安装 shell | `<DSH_HOME>/dsh-ops/shells` | renewable | explicit-command |
| R11 | Niubash 载荷替换（嵌套于 R9） | `<DSH_HOME>/dsh-ops/shells/niubash.{stage,previous}-*` | renewable | report-only |
| R9b | 工作区 ACL 备份 | `<DSH_HOME>/dsh-ops/acl-backups` | diagnostic | never-touch |
| R10 | 供装下载 scratch | `<OS temp>/dsh-ops-{bash,pwsh,niubash}-*` | renewable | report-only |
| R12 | 审阅探针 scratch | `<OS temp>/dsh-ops-review-*` | renewable | report-only |
| R13 | 仓库门禁 scratch | `<OS temp>/dsh-ops-{gate,pack,legacy-bash-fixture}-*`、`ops-ipc-build-*` | renewable | report-only |

R13 属于仓库门禁脚本而非随包插件，只有 `disk.status.includeRepository` 开启时才纳入。

## 回收证据

`reclaimableBytes` 只在存在真实归属证据时才非零。当前只有 R8：Bash IPC 缓存带托管标记与租约，因此 `bash-runtime clean-cache --yes --all-hosts-stopped` 能说出可回收项。其它可再生类别都报 0 并用 `reclaimBlocked.reason` 说明阻塞原因——目录名前缀、旧修改时间、死 PID 都不能证明没有 shell 后代仍在使用这些文件。

运维入口：

- `dsh-ops bash-runtime remove --yes` 删除带收据的托管 shell 副本。
- `dsh-ops bash-runtime clean-cache --yes --all-hosts-stopped` 回收空闲的 Bash IPC 代。
- `dsh-ops uninstall --yes` 删除整个 `<DSH_HOME>/dsh-ops` 树；它刻意宽泛，**不**是缓存生命周期已解决的证据，见[升级与卸载](升级与卸载.md)。

## 配置

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `disk.status.includeRepository` | false | 报告中是否纳入仓库门禁 scratch（R13） |
| `disk.status.maxEntries` | 5000 | 单个资源遍历上限 |
| `disk.retention.enabled` | false | 预留：本版没有任何淘汰实现 |
| `disk.retention.maxAgeDays` | 0 | 预留：0 表示全部保留 |
| `disk.retention.maxBytes` | 0 | 预留：0 表示全部保留 |

以上默认值与 `cordis.patch.yml` 一致。retention 键会被校验，好让后续切片在不破坏配置的前提下实现淘汰；本版没有任何删除逻辑读取它们。

## 报告刻意不扫描的内容

共享 npm/pnpm store、`Downloads`、实验区、Rust `target` 目录、其它插件的输出，以及声明家族之外的任何路径都不会被测量。这样只读报告不会在无意中变成清理工具。
