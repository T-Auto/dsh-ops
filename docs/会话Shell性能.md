## Windows 通道唤醒测量 — 2026-11-14

验收目标仍为 p50 ≤1 ms / p95 ≤3 ms，**尚未达标**。第一轮在通道封存时通知待连接操作；
第二轮同时改为等待读取线程句柄，去除 join 检查间的睡眠。两轮均保留物理输出排空、认证
EOF、受检查的溢写结算，以及释放缓冲区前等待已取消的重叠 I/O 完成。

| 配对轮次 | 基线空命令 p50 / p95 | 候选空命令 p50 / p95 | 基线 printf p50 / p95 | 候选 printf p50 / p95 |
| --- | --- | --- | --- | --- |
| 连接唤醒 | 46.48 / 48.77 ms | 16.05 / 17.22 ms | 46.61 / 49.45 ms | 16.54 / 28.25 ms |
| 连接唤醒及线程句柄等待 | 46.33 / 51.10 ms | 9.04 / 10.30 ms | 46.64 / 117.02 ms | 9.48 / 13.10 ms |

每轮在同一 Windows x64 主机先运行基线再运行候选：Ryzen 7 6800HS、15.2 GiB RAM、
Node 26.12.1、Rust 1.97.1 release 构建；与维护者的 i9-13900H 不同。
空命令预热 30 次后采样 300 次，printf 采样 100 次。完整运行保留原始 256 MiB 大块 I/O、
管道与朴素载荷对照，计时期间没有并发构建或测试。单轮配对不能证明尾延迟稳定；第二轮
基线 printf 的长尾如实报告，未过滤。

[原始报告与可执行 harness](../bench/probes/872/channel-wakeup-evidence/) 保留测量证据。
`compare.mjs` 仅增加可配置的可执行文件路径及 `OPS_DRIVER_SOURCE` 记录。设置 `OPS_ROOT`、
`OPS_NIU`、`OPS_DRIVER`、`OPS_DRIVER_SOURCE`、`REPORT`、`ONLY_NIU=1`、`SAMPLES=300`、
`WARMUP=30`、`BULK_MB=256`，使用 Node 运行。两个 driver 必须使用独立 Cargo target 目录；
早期共用目录曾复用出与基线相同的候选二进制，该无效候选已在测量前排除。

## 复用目录元数据 — 2026-11-14

C1 去除每个目录项的第二次绝对路径元数据查询。已持有目录句柄的禁止跟随元数据包含
符号链接类型及 Windows reparse 属性；读取内容和打开子目录保留既有检查。

使用未修改的 `bench/search-profile.mjs` 在同一 2,000 文件语料上交替运行前后版本：
`file0.ts` 至 `file1999.ts`，每个文件为 `export const valueN = 'hit';` 加换行。
总计 62,890 字节，语料 SHA-256 为
`de2bfa98c7e58d8203154462ef513fb88cf27fbab13d2b517d178ee10a31a3c3`。
每种查询保留三组首次访问/预热及 20 组正式测量。本次补充原生 worker 测量包含单次
进程启动和显式性能诊断，不等同于附件的 shell 场景或验收工作负载。

## 复用公开展示判定 — 2026-11-14

B1 复用步骤准备阶段已经获得的最终公开展示判定。缓存按 prompt 服务和精确的 agent
身份区分，公开的 `system-prompt/change`、`tools/change` 通知会使缓存失效。
执行仍然检查已准入定义、所属作用域和有效授权。跨越失效时刻的异步探针不能授权执行，
也不能覆盖更新的判定。未安装观察器的部署回退到重新公开装配；没有使用私有 executor
API，每个新 resolve 仍进行正常探针。

补充基准 `bench/probes/872/presentation.mjs` 使用真实 Cordis、工具及 prompt 服务、
作用域内 PTC executor、步骤准备，以及每步十次已准入的 SDK loader 回调。

## 会话通道池 — 2026-11-15

driver 现在持有三个有界通道池，十二个私有管道实例和十二个读取线程每个会话只创建
一次。每次借用仍分配全新的捕获状态、认证前缀、封存事件、取消控制和可选溢写归属；
构造时仍等待全部连接已就绪才公布端点。

读取任务仍将认证输出排空到自然 EOF，并完成溢写存储。所有待决操作被 join 后，
实例断开连接；任务销毁所捕获的资源后才发出本代完成信号。退役通道先清除句柄和
取消控制，再归还租约。保留的旧视图不变，关闭旧通道不能取消下一代。清理失败或
读取任务 panic 会禁止复用；收据解析、Job 成员身份、存活后代检查以及独立的会话
重置与取消边界全部保留。

上述 Windows 主机使用同一附件比较 harness（仅既有可执行路径覆盖），先旧版后新版：
30 次预热后 300 次空命令、100 次 printf，以及原来的 256 MiB bulk 项。

| 测量项 | 优化前 p50 / p95 | 优化后 p50 / p95 |
| --- | --- | --- |
| 空会话命令 | 8.66 / 9.70 ms | 6.90 / 8.84 ms |
| printf x | 8.61 / 9.68 ms | 6.52 / 7.29 ms |

[原始报告](../bench/probes/872/channel-pool-evidence/) 包含产物哈希。
旧 driver SHA-256：`13e554dc3ac5cef0ea7f16ac94a1acd1b850abd211a2458a01997e5b158db4c2`
（PR #944；#945 和 #946 不修改 driver）。新 driver SHA-256：
`4ae5f06e53ea36c18f3a52889ecf978b224f9956eadc2b7c03cd6630cb9aa120`。
两组采用相同 stock Niubash 与 Rust 1.97.1 release 构建。

新增的受控子进程回归验证：九代间固定的管道/线程身份、每代上限及视图、旧前缀拒绝、
独立已封存溢写文件、任务资源退役，以及 panic 后永久禁止复用。

池化使空命令中位数改善约 20%，但仍**不满足** 1 ms / 3 ms 目标。每个活跃会话仍有
十二个读取线程，每条命令仍需重新连接 MSYS 端点，并保留 driver 完成轮询。
完整 106 操作场景、冷启动和端到端宿主成本仍未测量。后续需继续削减固定成本，
不能用未经认证的输出标记替代 EOF，也不能削弱所有权保证。
