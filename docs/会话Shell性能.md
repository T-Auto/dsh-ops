## 会话通道池 — 2026-11-15

driver 现在持有三个有界通道池，十二个私有管道实例和十二个读取线程每个会话只创建
一次。每次借用仍分配全新的捕获状态、认证前缀、封存事件、取消控制和可选溢写归属；
构造时仍等待全部连接已就绪才公布端点。

读取任务仍将认证输出排空到自然 EOF，并完成溢写存储。所有待决操作被 join 后，
实例断开连接；任务销毁所捕获的资源后才发出本代完成信号。退役通道先清除句柄和
取消控制，再归还租约。保留的旧视图不变，关闭旧通道不能取消下一代。清理失败或
读取任务 panic 会禁止复用；收据解析、Job 成员身份、存活后代检查以及独立的会话
重置与取消边界全部保留。

上述 Windows 主机使用同一附件比较 harness（仅既有可执行路径覆盖），先旧版后新版：
30 次预热后 300 次空命令、100 次 printf，以及原来的 256 MiB bulk 项。

| 测量项 | 优化前 p50 / p95 | 优化后 p50 / p95 |
| --- | --- | --- |
| 空会话命令 | 8.66 / 9.70 ms | 6.90 / 8.84 ms |
| printf x | 8.61 / 9.68 ms | 6.52 / 7.29 ms |

[原始报告](../bench/probes/872/channel-pool-evidence/) 包含产物哈希。
旧 driver SHA-256：`13e554dc3ac5cef0ea7f16ac94a1acd1b850abd211a2458a01997e5b158db4c2`
（PR #944；#945 和 #946 不修改 driver）。新 driver SHA-256：
`4ae5f06e53ea36c18f3a52889ecf978b224f9956eadc2b7c03cd6630cb9aa120`。
两组采用相同 stock Niubash 与 Rust 1.97.1 release 构建。

新增的受控子进程回归验证：九代间固定的管道/线程身份、每代上限及视图、旧前缀拒绝、
独立已封存溢写文件、任务资源退役，以及 panic 后永久禁止复用。

池化使空命令中位数改善约 20%，但仍**不满足** 1 ms / 3 ms 目标。每个活跃会话仍有

不能用未经认证的输出标记替代 EOF，也不能削弱所有权保证。

## 通道进展通知 — 2026-11-15

命令和启动循环在检查通道前记录本代版本，然后等待版本变化。读取器在接收字节、
到达原始 EOF、完成溢写结算或报告终态错误后通知。版本票据保留检查与等待之间的
通知，避免丢失唤醒。每条命令独立持有通知，旧代不能唤醒或完成新代。通知只是提示：
收据解析、认证 EOF、Job 身份、未注册输出检查和通道退役 join 仍决定成功。
原子取消、诊断输出及 Job 退出尚未发布此通知，因此保留最多 2 ms 的回退等待。

使用同一比较 harness 和 stock 载荷，先旧版后新版；30 次预热后测量 300 次空命令、
100 次 printf，并保留 256 MiB bulk 项：

| 测量项 | 优化前 p50 / p95 | 优化后 p50 / p95 |
| --- | --- | --- |
| 空会话命令 | 6.63 / 7.32 ms | 4.45 / 6.32 ms |
| printf x | 6.63 / 7.31 ms | 4.66 / 5.28 ms |

[原始报告](../bench/probes/872/channel-progress-evidence/) 记录被测 driver 哈希；基线为
#947。真实管道回归在禁用进展通知时失败，恢复后通过，验证接收字节会唤醒观察者，
但不会宣称 EOF；另有测试覆盖提前通知及代际隔离。进程 crate 的 51 个测试全部通过
（6 个显式调用的子进程 fixture 忽略），release worker 的 12 个必需权限、准入、
输出、完整性、槽位及溢写套件全部通过，无跳过。

完整本地发布 gate 的 13 步也全部通过：749 个 Rust 测试、9 个忽略的子进程 fixture、
265 个 JavaScript 套件、4 个允许跳过项、92 个 manifest 检查及打包运行时闭包。
1 ms / 3 ms 目标仍未满足。上述微基准不包含宿主编排、冷启动或以下场景模型。

## Windows 祖先目录检查优化 — 2026-11-15

原生文件请求此前逐层查询祖先目录的元数据，再通过 cap-std 打开目录，并重复执行
若干检查。现在每层改为一次相对句柄的 `NtCreateFile` 目录打开，使用
`OBJ_DONT_REPARSE` 拒绝 reparse 点。打开器只接受单个分量：合并多层路径会绕过
原有的中间祖先读取权限检查。整个路径仍在 I/O 前完成词法校验，锚点、最终父目录
元数据、叶节点检查及内容打开均保留。读取权限掩码与读写共享方式保留既有的
父目录禁止删除租约。reparse 点及非目录祖先仍返回 `PATH_RESTRICTED`，真实
ACL 拒绝仍返回 `ACCESS_DENIED`。

[Windows 对象属性契约](https://learn.microsoft.com/en-us/windows/win32/api/ntdef/ns-ntdef-_object_attributes)
定义了 reparse 拒绝行为。真实夹具另行验证 junction 拒绝、逐层 ACL 拒绝、缺失
叶节点查询不创建文件，以及持有父目录期间禁止重命名。禁用 `OBJ_DONT_REPARSE`
会让 junction 回归失败，恢复后通过。另一个回归发现并修复了初版将普通文件祖先
的 `PATH_RESTRICTED` 错误变为 `IO_ERROR` 的兼容性问题。

本改动作用于原生文件工具，不改变会话 driver 或 Niubash shell 文件命令；原生
搜索测量不能替代 106 操作 shell 模型，也不能证明该模型通过验收。

`bench/search-profile.mjs` 在同一份 2,000 文件、62,890 字节语料上比较 #948 与
最终 release worker；先运行三组初始配对，再交替执行顺序收集 20 组测量配对。
期间不并行构建或测试，所有规范化结果一致，语料哈希不变。以下使用 nearest-rank
分位数，包含一次性 worker 启动及显式启用的阶段计时：

| 原生查询 | 改前 p50 / p95 | 改后 p50 / p95 |
| --- | --- | --- |
| 完整精确 grep | 2759.68 / 2839.61 ms | 1779.48 / 1907.16 ms |
| 有界 grep | 33.37 / 36.41 ms | 29.57 / 31.53 ms |
| 无匹配 grep | 2715.17 / 2794.85 ms | 1771.08 / 1888.31 ms |
| Glob | 218.98 / 243.87 ms | 215.96 / 245.62 ms |

[原始样本与溯源](../bench/probes/872/checked-parent-evidence/) 记录源码、worker 及

## UTF-8 命令记录 — 2026-11-15

原六行命令协议将每个 UTF-8 字节转换为五字节八进制转义，普通 ASCII 载荷因而
膨胀五倍。在固定版本 Niubash 中，包含中文或 emoji 的显式工作目录会以原始
字节载体字符进入 `cd`，导致会话重置。

记录编码器现保留 UTF-8 原文，仅转义 ASCII 控制字符与反斜杠。记录不包含真实
