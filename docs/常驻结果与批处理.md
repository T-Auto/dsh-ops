# 常驻结果与批处理执行

[English](resident-confined-workers.md)

Native 与 PTC 的 result put/page/release 共用同一桥接层，PTC 的 batch plan/run/resume
也走该桥接层。在 Windows 上，这些调用都使用所属常驻内核；公开 subprocess 服务只启动一次
内核，不再每次调用启动 OPS worker。原有引用与审计实现、ID、结果预算、写前记录、根目录和
会话绑定、no-follow 检查均保持不变。

权限边界明确区分：

| 当前策略与平台 | 执行路径 |
| --- | --- |
| 所有支持平台的完全访问 | 常驻内核内既有的可信固定 worker leaf。 |
| Windows 的只读或工作区写入 | 原始公开 `sandbox.confine()` 命令，在既有原子 Windows Job 范围内启动。 |
| POSIX 的只读或工作区写入 | 既有公开受限 runner；该平台尚未建立任意 runner 的原生所有权。这条剩余路径不是内核错误后的回退。 |

批处理只接受数据，但现有根目录相对路径检查并不被当作可移除 OS confinement 的证明。
受限 Windows 路径保留原始 argv、工作目录、公开清理后的父环境及 Electron Node-runner 适配。
结果报告真实的 confinement enforcement，保留 runner 失败及拒绝签名分类；不会向文件 worker
加入 shell 配置环境。异步准备结束后、派发前再次核对当前权限。

既有 `execute` 控制帧可携带仅供 batch/result 使用的可信启动信息。旧内核若缺少
`confined-worker-v1`，会在派发前拒绝请求。Envelope 仍限 2 MiB，启动信息限 64 KiB，共享
请求窗口仍为 32 个调用；不增加第二个调度器。取消与完成保持同一个 request ID。

请求字节发送前已建立所属进程范围。Started 回执先于有界 stdin 传输及 EOF，stdin 与两个输出
reader 均完成回收后才报告终态。原生 envelope deadline 覆盖启动、物理 started 确认、stdin 传输，
以及 worker 解码前停滞的 runner。既有有界回复队列在取消时仍保持 started 先于 completed。
已回收的输入传输错误不会抹去已知非零 runner 退出码或已捕获 stderr；超时与取消仍报告 interrupted。
取消会终止整个所属范围，包括公开 confinement wrapper。
无法确认回收时将连接置为不可用，而不报告清理成功。回执丢失不授权重放，中断的批处理继续保留
既有 unknown 效果状态，以及可用时的恢复审计标识。

缓存 purge 继续使用独立的常驻销毁路径。剩余一次性 transport 只服务于受限 POSIX batch/result
和明确启用的 WSL 读取。本切片不代表 POSIX 受限 runner 已迁移，也不代表议题 #872 已完成。

Windows 验证使用 worker SHA-256
`024d5e80b9befe77dce3b3ad4bf6c2d4d40e236047054acc79dd9f7196192b2c`。
8 项真实路由检查与 13 项 Native result 检查通过，覆盖公开 confinement、根链接替换、取消、
stdin 停滞、runner 提前拒绝，以及直到销毁结束均无公开一次性 OPS 启动。原有路径在最初 3 项
路由检查中全部失败；中间版本内核分别在 stdin deadline 和两个提前拒绝检查中失败。这些是
正确性与所有权观察，不是性能结果。
