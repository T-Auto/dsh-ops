# 真实语料工具调用耗时

English: [Real-corpus tool-call timing](benchmark-calls.md)。完整命令参考：[bench](../bench/README.md)。

`node bench/cli.mjs calls` 在不调用模型的情况下测量真实 host 派发的 `grep` 和 `glob`。
官方工具与 OPS、两个 OPS 版本共用同一套测试。测量按需执行；测试工装本身的正确性可以进
CI，耗时不作为 CI 性能门禁。

## 准备输入

先在运行测试的 checkout 中安装锁定的开发依赖。两个 OPS checkout 各自执行
`npm run build` 和 `cargo build --release --locked --manifest-path native/Cargo.toml`。
待测构建需提供现行的 `lib/components/file`、`lib/components/discovery` 和 `lib/policy.js`
接口；此 runner 不转换 0.3.x 的旧插件接口。

用不同目录保存两套构建即可，可以是现有 checkout，也可以是 worktree，不需要复制一套测试。
两臂共用**运行测试的 checkout** 中安装的 host 包，因此测的是同一宿主版本下的 OPS 改动，
不是 DSH 宿主升级前后的差异。

## 随仓库提供的语料

`bench/corpora` 提供四套 manifest。每套声明至少一个根目录，以及 shape 区间（文件数、MiB、
深度、二进制字节占比），runner 在测量前先校验。树本身由操作者按下表配方准备；证明“量的是
哪个版本”的是记录下来的内容身份，而不是目录名。

| 语料 | 类别 | 工作量 | case | 准备方式 |
| --- | --- | --- | ---: | --- |
| `harness-client` | source | 固定 commit 的 `packages/client`，3,155 文件 / 21.9 MiB | 8 | 在包含该 commit 的 clone 里 `git archive 22ddee3 packages/client`，解包后用 `--root` 指过去 |
| `python-stdlib` | runtime | 已安装的 CPython 标准库，4,121 文件 / 112.8 MiB | 8 | 使用 DSH 的 runtime 安装（身份校验 `python3.dll` / `python.exe`） |
| `rust-runtime` | runtime | rustup 工具链，66,077 文件 / 1,330 MiB | 4 | `rustup toolchain install 1.99.1 --profile default`，再用 `--root` 指向其目录 |
| `npm-runtime` | runtime | 本 checkout 已安装的 `@deepseek-ai` 包，6,077 文件 / 239.7 MiB | 8 | 本 checkout 自己 `npm ci` |

- 预算内语料（`harness-client`、`python-stdlib`、`npm-runtime`）携带八个 case：limit 5/50 的
  grep 完整/提前停止（`exactTotal` true/false）、无过滤无命中扫描、精确文件名 glob、无命中
  glob 与扩展名 glob。
- `rust-runtime`（66,077 文件 / 1,330 MiB）超出 10,000 文件 / 256 MiB 扫描预算，只带覆盖率
  case：无过滤无命中扫描加三个 glob。那里完整计数根本跑不完，命中对照只会变成两次截断扫描
  的比较，因此不声明。
- `npm-runtime` 没有自己的配方：它描述 runner 实际安装了什么，正好回答“我真正在跑的包”；
  你更新依赖时它的身份也会变。
- shape 描述的是配方产出的那棵树，不是任意 checkout：数字对不上时 runner 会拒绝，而不是把
  不同工作量记到同一个名字下。

## 执行对比

先建专用输出目录。以下 PowerShell 示例使用唯一临时目录，请将两个构建路径换成已有构建：

```powershell
$benchOutput = Join-Path ([IO.Path]::GetTempPath()) ('dsh-ops-call-test-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path $benchOutput | Out-Null

# 默认：官方工具与本 checkout 的 OPS 构建。
node bench/cli.mjs calls --corpus harness-client --warmup 2 --repeat 5 --out "$benchOutput/official-vs-ops.json"

# 当前 OPS 与候选 OPS，在同一进程内交替。
node bench/cli.mjs calls --corpus harness-client --baseline-plugin-root 'D:/builds/ops-current' --plugin-root 'D:/builds/ops-candidate' --warmup 2 --repeat 5 --out "$benchOutput/current-vs-candidate.json"
```

- 不传 `--baseline-plugin-root` 时默认测 `official,candidate`。
- 传入后默认测 `baseline,candidate`；加 `--projection official,baseline,candidate` 可同测三臂。
- 各 OPS 臂用自己的 `lib/`、工具命名策略和 release worker；`--baseline-worker` 与 `--worker`
  分别覆盖基线和候选的可执行文件。
- `--dry-run` 打印语料、各臂路径和调用计划，不启动 host、不写文件，也不校验构建。
  正式执行时，会先检查各臂构建再启动 host。
- `--baseline <previous.json>` 只检查当前语料与历史报告的身份是否一致，不选择 OPS 基线版本，
  也不把历史耗时与本轮样本配对。
- `--root` 覆盖单个语料的位置，用于在别处按配方准备好的树。每个报告路径必须尚不存在，
  不覆盖旧证据。

## 阅读证据

每套 manifest 都保留无过滤的 `grep-miss` 全扫描，并配有 limit 5/50 的 content 查询
（`exactTotal` true/false，#384）。`args.include` 映射到 OPS 的 `glob` 过滤条件。比较同一
OPS 查询的完整/提前停止版本，衡量取前几条结果的收益；`summary` 仍需全扫描。预算内语料还
回答精确文件名与无命中 glob 两个问题。

这些用例测量现有遍历，不评测 UFFS 或索引的建库、刷新、内存成本。官方工具是独立参照：
其 grep 没有调用级 `limit/exactTotal`，glob 按修改时间排序，并包含 OPS 排除的隐藏/依赖路径。
不同覆盖范围、排序与返回上限不能被当成等量工作。

同一 case 内各臂串行执行，每轮反转顺序。预热使用相同调度，但不计入实测行。
报告的 `arms` 记录各 OPS 臂的包版本、编译产物 `libSha256` 和 worker 路径/哈希，
官方臂记录工具包版本。原有顶层 `pluginRoot` 与 `worker` 仍指候选；未选候选时为 null。

各 case/arm 的 `arguments` 记录实际派发参数，包括 OPS 覆盖值。coverage 增加可获得的
`matchedObserved`、`matchedTotal` 和 `displayedItems`；缺失事实为 null，不是零。
提前停止只提供下界，不代表精确总数。

`corpora[].rows` 保留执行臂、轮次和顺序、派发到结果的 `durationMs`、子进程 `spawnMs`、
输出字节数、覆盖率和错误。每个 case 再按臂汇总。总时间已包含子进程时间，不能把两者再相加。

耗时必须和扫描完整性、截断、跳过文件及输出语义一起看。两个版本共用逻辑查询和 OPS 参数覆盖，
工装并不证明结果语义等价。提前停止可能因少做工作而显得更快，官方工具也不暴露同样的覆盖率信息。

`firstMs` 是丢弃预热后的首次**实测**，即便 `--warmup 0` 也不能保证 OS 缓存为冷态。
`steadyMs` / `convergedAt` 表示相对最后样本落在 10% 带内的尾部；仅一个尾部样本不能证明稳态。
看到耗时仍在下降的提示时应增加预热。同进程交替能减轻执行顺序漂移，不能消除机器噪声或让耗时跨机器可复现。

退出 `0` 表示实测调用和语料检查成功，`1` 表示证据不可用（调用报错、输入变化、形状或身份不符），
`2` 表示参数或输入/构建缺失，都不表示“候选更慢”。验证工装时可先让两版本臂指向同一构建；
这属于 A/A 检查，不是提速证据。

## CI 覆盖

默认套件清单包含 `bench-calls`、`bench-call-versions` 和 `bench-gates-errors`，用确定性夹具
验证参数、语料身份、不同插件加载、执行顺序和错误报告，不断言耗时或模型成本。
已安装真实语料和跨版本性能测量继续作为手动证据。
