# 配置参考

[English](configuration-reference.md) | 中文

OPS 沿用单行插件页：bundle 只插入一个 `dsh-ops` 行。内置预设和显式配置的自定义预设共用消费者装配流程；仅安装不会接管未知预设。插件作者也可独立挂载[公开集成接口](集成接口.md)。

## 单行开关

| 分区 | 默认与行为 |
| --- | --- |
| `global` | `bash`、`hidePwsh`、`hideOfficialTools`、`dynamicTools` 默认 true，门控该行管理的消费者对应选项；另含默认 true 的 `forceDefaultOpsPtc`，见下一行 |
| `global.forceDefaultOpsPtc` | 默认 true；开启时在 `ops-ptc` 注册成功后把默认预设强制为 `ops-ptc`（运行时经宿主 settings 服务写 `selectedDefault`，与设置页同一机制，覆盖手动选择）；关闭或禁用/卸载插件行时恢复强制前的值，未捕获或捕获值本身是 `ops-ptc` 时回退宿主 `config.default`（官方默认）；只有预设注册成功才强制，失败只告警 |
| `minimal` | 默认开启；无基础文件常驻面，可启用 Bash 和动态选择 |
| `standard`、`cordis` | 默认开启；Native 常驻读取/搜索/分页，可选 Bash、替换与发现 |
| `ptc` | 默认开启；真实宿主 PTC 展示下的类型化常驻 API 和渐进式 SDK |
| `ops-ptc` | 默认开启；第五个内置增强模式，发布面与 PTC 相同，预设由插件运行时注册；另带可选的批量调用上下文提示（`batchingGuidance`，代码默认 false，随包 `ops-ptc` 节置 true） |
| `presets` | 默认空；精确 preset id 到显式消费者选项的映射 |
| `discovery` | 默认开启；内置 Native 池、maxResults=3、无启动选择 |
| `panel`、`tui` | 默认关闭；采集与只读侧栏 |
| `resultCache` | 默认开启；启动与最后一个所有者卸载后回收空闲结果缓存根。`maxRoots`/`maxTotalBytes` 默认 0（仅报告），`maxAgeMs` 默认 3600000（空闲宽限），`sweepEnabled` 默认 true |
| `other.pwsh7Link` | 未保存时跟随联动检测，已保存布尔值优先 |
| `disk` | 只读归属报告；`status.includeRepository` 默认 false、`status.maxEntries` 默认 5000；`retention` 块只是经校验的契约（本版没有淘汰实现） |

`disk.status.*` 与预留的 `disk.retention.*` 键仅在 YAML 中配置。资源清单、只读的 `dsh-ops disk status` 报告，以及它刻意不扫描的内容见[磁盘与缓存](磁盘与缓存.md)。

页面使用原生 Switch。内置卡片默认收起；关闭卡片只置灰，不清除保存值。Standard/PTC/OPS PTC/Cordis 提供默认开启的 `residentTools`，与动态加载独立；Minimal 保留不常驻的产品默认，若要改变可用 `presets.minimal` 显式选择。Bash 独立发布；文件替换和 Windows 宿主 PowerShell 隐藏也彼此独立。

总开关作与门控，不覆盖消费者保存意图。pwsh7 联动强制关闭该行管理消费者的 `hidePwsh`，让宿主 Shell 保持可见供 `dsh-win-pwsh7` 使用。未保存即「没碰过」：保存其它开关不会把检测结果写成显式值，而手动拨动联动开关一定落盘（开、关都写）；检测读的是安装本包的 profile，因此宿主进程里没有 `DSH_PROFILE_DIR` 也能判定。这些是工具发布选项，不是文件系统授权，不会绕过宿主权限。

「强制默认模式为 ops_ptc」（`global.forceDefaultOpsPtc`）只决定新会话默认使用哪个预设，不改变任何工具发布面或权限。它与「Agent 预设」设置页写的是同一个 `selectedDefault` 字段：开启时会在 `ops-ptc` 注册成功后强制写 `ops-ptc`，因此手动选过别的默认也会被覆盖；关闭时恢复开启前捕获的值，未捕获则回退官方默认 `config.default`。宿主 settings 服务缺失或写入失败只记 warning，不影响其它功能。

保存只写改动字段的精确嵌套路径，并带页面读到的 revision；冲突保留草稿，重置读取当前保存值。运行时状态区展示真实平台、受管理/Git Bash、PowerShell 与联动事实；安装/删除须先预览再明确执行，配置保存不部署二进制，也不改 PATH。

## OPS PTC 模式（`ops-ptc`）

`ops-ptc` 是第五个内置增强模式（preset id 与单行分区名都是 `ops-ptc`）。发布面与官方 PTC 相同：
宿主真实 PTC 呈现下只有一个 `run_code`，同栈类型化 SDK 文件工具由本插件发布；压缩沿用官方
`compaction-basic`，不引入 `dsh-compress-codex`。它与 `ptc` 分区的配置键相同，行为差异只有
`batchingGuidance` 一项。该预设由插件在 `apply` 时通过宿主 `agentPresets.register` 运行时注册，定义来自
随包片段 `presets/ops-ptc.patch.yml`（由宿主 `loadOverlayPatches` 解析）；插件管理器里没有对应预设行，
禁用 `dsh-ops` 行会连同预设一起移除。预设在宿主选择器里的名称是 `OPS (PTC)`，描述为「代码驱动的 PTC 工具面，由 dsh-ops 的 ops_* 工具扩展。」；默认预设是否指向它由 `global.forceDefaultOpsPtc` 控制（默认开启），片段生成、强制/手动默认的差异与回退见[预设与默认模式](预设与默认模式.md)。

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | true | 对 `ops-ptc` 预设的会话发布本模式工具面；插件页有开关，YAML 也可设置 |
| `residentTools` | true | 发布启动 API。PTC 常驻面只有 `ops_inspect_local_file`，其余按需通过 `ops_load_sdk` 加载 |
| `bash` | true | 允许为 Windows 会话发布 `ops_bash`；POSIX 沿用宿主 bash |
| `hidePwsh` | true | Bash 可用时隐藏 Windows 官方 shell；`global.hidePwsh` 为 false 时整体失效 |
| `hideOfficialTools` | true | 隐藏本模式替代的官方文件工具；`global.hideOfficialTools` 为 false 时整体失效 |
| `dynamicTools` | true | 发布渐进式 SDK 加载器 `ops_load_sdk`；与 `global.dynamicTools` 同时开启才生效（与门） |
| `batchingGuidance` | false | 会话首轮注入一次，并在同轮同路径连续 3 次写入后随工具结果再注入一次；文案来自可编辑的 `prompts/batching-guidance.md`。仅 YAML 可配，插件页不暴露；随包 `cordis.patch.yml` 的 `ops-ptc` 节置 true |
| `spillRetentionDays` | 30 | 宿主 subprocess spill 保留窗口；`0` 只报告、永不删除 |
| `spillTotalBudgetMiB` | 256 | 保留总字节预算（MiB）；`0` 关闭预算 |
| `spillSweepEnabled` | true | 组件激活时与每 256 次结算后执行一次有界清扫 |

其余 `binaryPath`、`required`、`denyCredentialReads`、`promptPolicy`、`extraGuidance`、
`allowSystemShellFallback`、`allowedTools`、`alwaysLoaded` 的取值与含义和 PTC 行一致
（`extraGuidance` 只用于 Native 提示词；`allowedTools`/`alwaysLoaded` 只接受可加载的原始 API 名，
见 [PTC SDK 按需加载](PTC按需加载.md)）。三个 `spill*` 键作用于宿主 subprocess spill 保留，
语义见下文「内置高级配置」。

### 批量调用提示（`batchingGuidance`）

关闭时（代码默认）不产生任何额外上下文。开启后提示分两处投递，文案来自外置英文 Markdown：

- **会话首轮一次**：在会话第一个被接受的非空用户消息批次里追加一条插件上下文（step-tail，来源
  `dsh-ops:step-tail` / `batching-guidance`），它进入会话历史，模型第一条请求即可看到完整范式：首行
  `// plan:` 指令、按依赖拆分、先加载再调用，以及四条可照抄的轨迹。
- **薄程序触发**：**根** `run_code` 程序命中三类锁中的一类时，在该次调用的结果上以 `additionalContexts`
  追加一条短提醒。工具结果的值、正文与既有上下文都不变，程序既不阻断也不改写。
- 三类分别是 `bypass`（用 shell 或 `node:fs` 做文件工作）、`plan`（第一物理行没有 `// plan:`）与 `shape`
  （一次往返只做一件事）。每类每轮各锁一次；某个类别一旦合规即解锁，所以同一轮内先改对再退回还会再次
  提醒，不设每轮条数上限。
- 投递优先级为 `bypass` → `plan` → `shape`，一个程序最多得到一条提醒。
- 只检查根调用（`exec.parent === undefined`）。嵌套的 `tools.ops_*` 属于 PTC 执行层，说明不了这一步的形状。
- 分析是对程序文本的字面启发式：循环或 `map` 只算一个调用站点，不是运行时扇出；字符串与注释也可能误导。
  提醒文案会说明这一点，不宣称实测的 dispatch 数；被取消或从未派发的调用不参与分析。
- 全部都是插件上下文历史，tool schema 不变，系统提示词与其缓存因此不受影响。教学只有在真正出现持久
  `user/message` 时才算兑现；因取消或拒绝而撤回的批次不会消耗它，下一个被接受的批次仍会教学。

`batchingTelemetry`（同一行、YAML-only、默认 `false`）每投递一条提醒打印一行结构化日志，例如
`dsh-ops batching: turn=3 category=plan plan=1 bypass=0 shape=2 total=3`。它只做观测：不产生上下文、
不发消息、不引入新依赖。

文案文件是 `prompts/batching-guidance.md`（随包发布，英文、软编码，可直接编辑）。进程内按路径读取一次
并缓存，改完重启生效；读不到文件时打印一次 warning 并跳过投递，空文件同样跳过；投递失败只记一条
warning，不改写工具结果。

**对照臂用法。** 想在同一套 PTC 发布面上比较提示效果时，让 `ptc` 与 `ops-ptc` 两个分区保留相同的 API
配置，只在 `ops-ptc` 节置 `batchingGuidance: true`（随包默认），或反过来在 `ptc` 节置 true 复核提示本身；
把 `ops-ptc` 节置 false 即回到无提示基准。两个键都是 YAML-only：插件页没有开关，且已保存的 `dsh-ops` 行
覆盖会整体替换随包配置，升级后请在覆盖里显式补上（见[预设与默认模式](预设与默认模式.md#风险与回退)）。

## 自定义消费者

```yaml
presets:
  acme-chat:
    enabled: true
    files: true
    residentTools: true
    residentNames: [read_files, stat]
    shell: false
    hidePwsh: false
    discovery: true
    allowedTools: [diff, grep]
    alwaysLoaded: [diff]
    replaceOfficial: false
    promptPolicy: true
    extraGuidance: Use bounded repository inspection.
    externalTools: [acme_lookup]
    externalAlwaysLoaded: []
    externalDisabled: []
```

映射键就是精确 preset id，内部不要重复写 `preset`。已配置项出现在同一个原生开关页，提供启用、文件、常驻、Shell、隐藏、发现、指导开关。宿主 descriptor 同时接受详细配置；名称列表与运行时路径可在 YAML 保存。带点的 id 是完整路径段，不会被拆成嵌套对象。

未列出的预设保持原样。显式配置内置 id 时，两种挂载顺序都会覆盖内置默认。`enabled: false` 保留显式禁用绑定，不回退到内置工具面；作用域诊断仍可访问。

| 选项 | 默认与含义 |
| --- | --- |
| `profile` | 默认 native，快捷档为 native/ptc/discovery/shell |
| `files` | native/PTC 为 true，discovery/shell 为 false；控制内置文件常驻面 |
| `residentTools` | true；关闭基础常驻，不抹去显式发现选择 |
| `residentNames` | Native 原始名称列表，默认 inspect_local_file/glob/grep，read_files/result 按需发现；可以为空 |
| `shell` | 除 shell profile 外默认 false；宿主授权的常驻 Bash，不属于发现池 |
| `hidePwsh` | 默认 replaceOfficial && shell；独立控制 Windows 宿主 Shell 隐藏 |
| `presentation` | 除 PTC profile 外默认 native；只选投影，不改变宿主展示 |
| `discovery` | 除 shell profile 外默认 true；关闭选择入口/SDK loader，但保留显式启动选择 |
| `allowedTools` | 发现开启时默认所有可加载能力，否则空 |
| `alwaysLoaded` | 空，必须在允许列表内；与 Native 常驻集合独立 |
| `replaceOfficial` | false；只替换实际就绪且本步准入的对应项；条件项可能保留原版可见 |
| `promptPolicy` | true；指导只广告实际发布的工具 |
| `extraGuidance` | 空，Native 专属；PTC 明确拒绝 |
| `externalTools`/`externalAlwaysLoaded`/`externalDisabled` | 默认空，外部允许/启动/禁用名单，禁用优先 |
| `binaryPath`/`bashPath` | 默认受管理解析，可显式指定 |
| `required` | false；所需 worker 缺失时拒绝激活 |
| `denyCredentialReads` | true，Native 可显式覆盖；PTC 拒绝覆盖并持续执行边界 |
| `downloadGuard.template` | 空；未设置时不生效。建议命令包含独立且未加引号的 `{url}`（必需）与可选 `{file}` 参数，绝不自动执行 |
| `downloadGuard.shell` | 默认 `bash`；`pwsh` 对建议参数采用 PowerShell 引用方式。可选配置段与检测边界见[下载约束](download-guard.zh.md) |
| `allowSystemShellFallback` | false；保留兼容，不开启 Windows 隐式 Bash 回退；请显式设置 `bashPath` |

0.5 中，开启原版工具替换不保证条件性工具从模型工具表消失。OPS 对应项采用条件准入时，原版注册仍可见；只有同一已捕获步骤 toolSet 准入该对应项且消费者当前仍有权限时，OPS 才在分派时拒绝原版调用。对应项缺失、撤销或尚未就绪时，不得连带禁用原版工具。安全的无条件常驻替换仍可使用宿主限制。OPS 不包装原版定义，也不在准入条件或提示词组装中隐藏工具。

`shell: false` 保留显式 `bashPath`、`allowSystemShellFallback` 与 `hidePwsh` 意图，但不发布 Bash、不隐藏宿主 Shell；重新启用时应用保存值。自定义 PTC 卡片锁定 `files` 开启，并提示用 `residentTools` 控制启动 API。PTC 必须 `files: true`，且宿主真实为 run_code-only 展示并有 PTC runtime；不接受 `residentNames`，不把外部 Native 提供者当类型化 SDK。[第三方 PTC 注册暂不支持](外部工具提供者.md)。

独立 `integration({ preset, ...options })` 使用同样选项和装配器，但归其挂载插件所有，不由无关 bundle 总开关控制。同 id/同 scope 不重复绑定；见[作用域与生命周期边界](集成接口.md#生命周期与归属)。

## 内置高级配置

内置分区保留 worker/Shell 配置：`binaryPath`、`required`、`bashPath`、`denyCredentialReads`、`promptPolicy`、`extraGuidance`、`allowSystemShellFallback`，以及 `publishBashTool` 作为 bash 的历史别名。`ptc.allowedTools`/`ptc.alwaysLoaded` 控制类型化 SDK；`discovery.allowedTools`/`discovery.alwaysLoaded` 控制内置 Native 池。全面客制化使用 `presets.<id>`，不要继续在核心添加 preset 名称特判。`resultCache` 是 YAML 配置段：默认清扫只回收不含快照数据的根（空根或只剩 lock）；聚合根数/字节预算默认 0，超预算的根只在报告中标为 blocked，清扫永不删除仍含快照数据的根。`dsh-ops result-cache status|reclaim [--apply]` 报告并执行同一次有界清扫。

宿主 subprocess spill 的保留由另外三个内置键约束：`spillRetentionDays`（默认 30；`0` 只报告、永不删除）是作用于 spill 文件 mtime 的窗口；`spillTotalBudgetMiB`（默认 256；`0` 关闭预算）限制保留总字节，最旧优先淘汰；`spillSweepEnabled`（默认 true）控制组件激活时与每 256 次结算后的自动 pass。只有结算时登记在 `<DSH_HOME>/ops-spill-ledger.jsonl` 的路径才可能被处理，单次 pass 最多删除 64 个文件，且永不删除宿主的 `dsh-subprocess-*` 目录。用 `dsh-ops bash-runtime spill-report` 查看并按需清扫（见[使用指南](使用指南.md)）。

`discovery.enabled` 只控制内置 Native 发现入口，不控制 PTC SDK loader；后者由 `ptc.dynamicTools` 与 `global.dynamicTools` 控制。Native 配置其余键为 maxResults（1–5，默认3）、allowedTools、alwaysLoaded、binaryPath、required、denyCredentialReads。启动名单必须被允许；动态入口还须预设与全局动态开关同时开启。Native 与 PTC 的选择均不执行工具动作，下一模型步骤才激活。

## 凭据与执行边界

凭据围栏覆盖所有方向：拒绝的路径不能作为读取源、写入或 copy/move 目标，也不能被删除。历史名 `denyCredentialReads` 因而不只保护读取；danger-full-access 也默认开启。拒绝为 CREDENTIAL_DENIED、无效果、不可重试，不泄露路径或父目录。DSH_OPS_DENY_READ 可扩大围栏。Native 显式关闭是操作者配置，不是额外授权。

Windows Niubash 选择阶段校验冻结源载荷，按清单哈希在 `<DSH_HOME>/dsh-ops/shells/niubash-prepared/<manifest hash>` 复制准备一次，包含命令 face 和六个启动目录，不与源文件建立硬链接。常规调用复用该运行时，不再克隆、哈希、封印或写执行收据，每次调用仍遵循当前宿主策略（受限模式执行 confine）。`DSH_HOME` 必须使准备目录位于会话工作区外，每次调用都检查此边界。`DSH_OPS_EXEC_ROOT` 与 `NIUBASH_VERIFY=deep` 已弃用，运行时忽略；只有离线旧执行树回收仍读取 `DSH_OPS_EXEC_ROOT` 来发现旧目录。准备版本损坏时，选择阶段会移走旧版本并从已验证源载荷重建一次；修复失败同时报告两次错误，不循环重建。成功选择后，旧准备版本及 broken/retired 残留和所选哈希自身的 stage 残留会先改名为 `.retired-<uuid>` 兄弟目录，再尽力删除；只处理精确匹配准备版本名称的真实目录，改名失败本次不重试，留待下次选择。`cache status/reclaim --kind exec-tree` 也列出/回收这些非当前准备目录（包括其他哈希的 stage 残留），绝不回收当前哈希目录。若同一 DSH_HOME 的另一 profile 使用不同 Niubash pin 并退役了所选版本，下次调用会从原选定的已验证源重新准备该 pin 一次，此路径不退役其他版本。

Windows 受限模式下的自定义 MSYS Bash 必须使用固定构建和经校验的私有 IPC 代理；不兼容的自定义 Bash 报 EXECUTOR_UNAVAILABLE，不得绕过约束或换 Shell 修复。POSIX 使用宿主 Bash 与宿主沙箱。显式 worker/Shell 路径失败时不偷偷换执行器。PowerShell 安装是独立宿主操作，OPS 不捆绑或覆盖宿主 PowerShell。

## 采集与侧栏

`panel.enabled` 控制采集；启用内部 capture 默认 true，旧显式 false 仍关闭。textLimit 为64–100000（默认2000），maxSessionBytes 为65536–268435456（默认8388608）。只写会话工作区 `.dsh-ops/panel/`，不写真实 DSH home。报告可能包含对话和工具正文，须 Git 忽略。停止会取消排队 I/O、等待已发工作，保留可恢复 NDJSON，不自动做最后折叠。tui 仅接受 maxSessions/maxActive/recentLimit，不授予执行能力；见[侧栏](tui-panel.zh.md)。

## 迁移

bundle 不再插入 mode-*、discovery、compat、panel、tui、shell、file、ptc、hide-official 或 background 独立行。迁移值到单行后删除旧覆盖，OPS 不自动重写 profile。保留的 legacy 组件在 merged bundle 下告警并保持惰性。`dsh-ops/compat` 已随旧兼容开关移除；用 hideOfficialTools/replaceOfficial=false 和 hidePwsh=false 保留原版工具。

旧 FastCtx 键只做保存配置迁移的类型校验，不启用旧执行器。configUpdateVersion 是迁移标记，不是能力开关；shellPolicy、deniedHostTools、replaceTools 及旧隐藏字段不属于当前消费者。
