# 配置参考

按组件说明每个配置键，以及**哪个键属于哪个组件行**。

---

## 配置的位置

在 DSH 的配置编辑器中找到对应的 `dsh-ops/shell`、`dsh-ops`（file）、`dsh-ops/background` 或 `dsh-ops/ptc` 行，调整 `config` 后保存；未知配置键会点名报错。

文件行由 `dsh-ops/file` 改用根入口 `dsh-ops`，id 仍为 `dsh-ops-file`；根入口原本就是 file 的别名，没有增删组件。旧 `/file` 入口仍有效，但纯子路径的手写 composition 不会发现浏览器 companion；需要根入口文件行才能显示配置 UI。

GUI 中打开「插件 → dsh-ops → 文件行 → 配置」，只有一个「隐藏官方基础工具」开关（`hideBuiltinTools`，默认关闭）；通过 `volatile` + `configForms` 切换即保存并生效。

Bundle 声明四个组件，分别启停，首次安装默认开启前两个：

| 配置行 `name` | 组件 | 默认 |
| --- | --- | --- |
| `dsh-ops/shell` | 终端与 shell | 开 |
| `dsh-ops` | Rust 文件工具 | 开 |
| `dsh-ops/background` | 后台任务 | 关 |
| `dsh-ops/ptc` | 原生 PTC 批处理 | 关 |

## 🔴 键与组件的归属关系

下表是**每个键属于哪个组件**。把键填到不拥有它的那一行，会被配置校验拒绝并点名该键。

| 配置键 | 类型 | 默认 | 归属组件 |
| --- | --- | --- | --- |
| `configUpdateVersion` | 非负整数 | `0` | 任意（迁移标记） |
| `serverName` | 字符串，`[A-Za-z0-9_-]{1,32}` | `fastctx` | 兼容保留 |
| `binaryPath` | 字符串路径 | — | background / ptc |
| `bashPath` | 字符串路径 | — | shell |
| `enableShellTools` | 布尔 | `true` | background |
| `publishBashTool` | 布尔 | `true` | shell |
| `hideBuiltinTools` | 布尔 | `false` | file / 根入口 `dsh-ops` |
| `promptPolicy` | 布尔 | `true` | 全部 |
| `extraGuidance` | 字符串 | 空 | 全部 |
| `toolCallTimeoutMs` | 正整数（毫秒） | `300000` | background / file |
| `required` | 布尔 | `false` | 全部 |
| `shellPolicy` | `advise` \| `deny-host-shell` | `advise` | shell |
| `deniedHostTools` | 字符串数组 | `[pwsh, bash, pwsh_persistent]` | shell |
| `allowSystemShellFallback` | 布尔 | `false` | shell |

## 示例

`dsh-ops/shell` 行：

```yaml
config:
  promptPolicy: true
  publishBashTool: true
  shellPolicy: advise
  allowSystemShellFallback: false
  # bashPath: 'C:\tools\bash.exe'   # 仅在 danger-full-access 下生效，见下方 bashPath 说明
```

`dsh-ops/background` 行（其市场行默认禁用）：

```yaml
config:
  promptPolicy: true
  enableShellTools: true
  required: false
  toolCallTimeoutMs: 300000
  # binaryPath: 'C:\tools\fastctx.exe'
  # Managed update metadata; do not remove after the first startup self-check
  # configUpdateVersion: 1
```

## 逐个说明

- `enableShellTools`：后台组件的部署开关，开启仍须会话 `danger-full-access` 才发布四个后台工具；文件组件不发布命令工具。
- `publishBashTool`：是否发布 `ops_bash`；读取最新会话权限，受限模式需宿主 sandbox，完全权限使用宿主 subprocess。
- `hideBuiltinTools`：默认 `false`，仅 file/root 拥有。开启仅隐藏并拒绝调用 `read/write/edit/glob/grep/bash/pwsh/pwsh_persistent`；保留 `read_image`、第三方工具、`run_code`、`ops_batch`、`ops_result` 和后台 `ops_*`，不是删除所有非 ops 工具。不改变沙箱/权限；若可用的 ops 工具无法完成任务，关闭即可恢复。停用 file 或卸载也会撤销隐藏；独立 `shellPolicy` 的拒绝仍保持。
- `promptPolicy`：是否注入该组件的运行时说明；可用 `extraGuidance` 追加指导。
- `toolCallTimeoutMs`：FastCtx RPC 等待超时，不代表服务端工作已终止。上限 `2147483647`。
- `required`：运行时不可用时是否拒绝激活。
- `shellPolicy`：默认 `advise`；`deny-host-shell` 拒绝 `deniedHostTools` 列表中的宿主 shell（默认 `[pwsh, bash, pwsh_persistent]`）。这也会禁用第三层 pwsh，谨慎开启。
- `allowSystemShellFallback`：默认 `false`，随包/已 provision 的 bash 缺失时不探测系统 PATH 或常见安装目录；后台组件也不绕过此选择调用 FastCtx 的自动探测。只有显式设 `true` 才使用未固定摘要的系统 bash，请自行信任与维护该执行器。显式 `bashPath` 是另一种操作者选择，并非自动回退。首次升级启动的迁移见 [使用指南](使用指南.md) 的「更新配置修改区」。
- `shellPolicy` 与此开关独立：`deny-host-shell` 遮蔽/拒绝宿主工具；禁止系统回退只约束插件自己的 bash 解析，不关闭宿主 `pwsh`，也不提供文件系统沙箱。
- `binaryPath` / `bashPath`：可选显式路径；不可用时报错，不悄悄换执行器。一般无需配置。
- `bashPath` **仅在 `danger-full-access` 下生效。** 只读与工作区内修改模式下，`ops_bash` 只运行已校验 IPC 兼容代理的固定摘要 MSYS（随包载荷或 `dsh-ops provision-shells --bash`）；其它任何 `msys-2.0.dll`（包括你自己的 Git for Windows）都会按设计返回 `EXECUTOR_UNAVAILABLE`，且绝不裸执行。不要把 `bashPath` 指向自带 Git Bash 来规避受限模式问题。可用 `dsh-ops ladder --config <文件>` 检查所选 bash，报告中的 `restricted: yes/no` 即受限模式能否运行。见 [常见问题](常见问题.md#受限模式下-ops_bash-无法运行自定义-bashpath-或-git-for-windows)。
- `deniedHostTools`：`deny-host-shell` 策略下拒绝的宿主工具名列表。
- `serverName`：FastCtx 服务器的历史标识，为既有部署行保留；服务器说明不再作为独立 prompt 段发布。
- `configUpdateVersion`：一次性配置迁移的完成标记。不要删除迁移标记，否则会重新自检。

## 提示词注册

提示词注册为独立运行时段，**不写 AGENTS.md**：Shell 关就撤销 bash/pwsh 路由；文件关就撤销原生文件说明；后台关就不发布后台工具及自有 job 指导。文件组件使用独立 Rust worker；FastCtx 仅由默认关闭的 background 组件保留。默认新增四个原生文件工具和 `ops_bash`，不发布重复前台 `ops_run`。这些改变减少固定声明成本。极简预设会覆盖附加 system sections；PTC 模式经 SDK 调用底层工具，权限门不变。
