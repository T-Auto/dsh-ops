# 内部架构

[English](internal-architecture.md) | 中文

OPS 是主动接入的能力增强层。内置预设是默认消费者方案，不是工具的另一份实现；外部预设通过同一个装配流程使用能力。

## 职责目录

| 目录 | 职责 |
| --- | --- |
| `integration/` | 稳定的 `dsh-ops/integration` 公开入口与作用域诊断 |
| `consumer/` | 预设身份、显式绑定、配置校验、消费者计划与统一装配 |
| `presets/` | 内置产品默认方案、保存配置的兼容解析；不定义通用发布策略 |
| `capabilities/` | 工具契约、修改属性、参数归一化及常驻能力集合 |
| `discovery/` | 提供者元数据、统一候选排序、下一步选择及动态发布 |
| `publication/` | 作用域所有权、协调事务、Native/PTC 发布、展示与替换屏蔽 |
| `execution/` | worker 解析、有界传输、固定文件权限桥与受限 batch/result 桥 |
| `projections/native/` | 面向模型的紧凑文本及读取证据 |
| `projections/ptc/` | 类型化 Outcome、schema 与渐进式 SDK 投影 |
| `lifecycle/` | 调用的协作式取消、时限与等待结算 |
| `kernel/` | 公共结果词汇、调用预算及会话结果存储和生命周期 |
| `adapter/dsh/` | 宿主类型、延迟加载及浏览器原生控件适配 |
| `settings/`、`client/` | 单行配置校验、profile 保存与原生控件界面 |
| `shells/` | Shell 解析、准入、宿主执行与作业 |
| `panel/`、`tui/` | 可选采集及只读界面联动 |
| `legacy/` | 单行配置之前的组件兼容入口 |

`src/index.ts` 只负责单行组合；`consumer/mount.ts` 是内置与显式消费者共用的当前装配入口。`presets/builtin.ts` 将内置默认与保存开关翻译为计划，`integration/index.ts` 将公开选项翻译为相同计划。配置预设 id 不会改变宿主展示或授予权限。

## 执行共享，投影分开

Native 文件工具和 PTC 文件 API 都调用 `execution/files.ts`，进入同一个 Rust 内核。batch/result 使用 `execution/jobs.ts`，两条桥均复用 `execution/transport.ts`。固定文件路径保留可信数据操作策略，batch 保留宿主进程约束；共享传输不等于取消两者的安全差异。

Native 文本与 PTC 类型化数据有意分开。文本 renderer 不是类型化 SDK 契约。目前第三方提供者仅支持 Native；外部 PTC SDK 注册明确不支持，不从预设名称猜测。

## 生命周期与发布

`lifecycle/invocations.ts` 将调用绑定到消费者及调用者 signal；外部调用同时绑定提供者实例。消费者卸载、Agent 退出、预设/展示/权限撤销会取消所属调用。可信 worker 调用在卸载时等待结算；外部提供者的发布会撤回，不会无限等待任意第三方 promise，未完成调用以警告明确副作用可能未知。AbortSignal 不是强制隔离，提供者仍负责执行与授权，并须响应取消。

选择先进入 pending，下一模型步骤才激活；不执行工具，也不改写当前请求快照。提供者重装会生成新 token，不继承旧实例的选择。内置和外部元数据在同一候选池排序后再应用结果上限。

## 兼容与边界

有明确兼容语义的组件导出继续保留。旧 `file/`、`modes/` 及根帮助文件是薄 reexport；`ptc/` 仍保留配置与执行契约接缝，投影和发布实现已迁入职责目录。这些私有接缝不是新增的公开 API。新消费者只应导入 `dsh-ops/integration`，不要引用私有 `lib/*`。

单行改造后悬空的 `dsh-ops/compat` 导出已删除。内置配置使用 `hideOfficialTools: false`，显式消费者使用 `replaceOfficial: false` 保留原版文件工具；Shell 隐藏由 `hidePwsh` 独立控制。

宿主会继承祖先注册与屏蔽。无关预设应作为平行 sibling composition，不要嵌在已接入预设下面。OPS 会拒绝错误消费者使用继承回调，但不承诺在这种不支持的嵌套边界隔离 schema。

## 验证

- `test/consumer-assembly.test.mjs`：显式覆盖、自定义配置、外部取消、晚到权限服务、统一评分及调用所有权。
- `test/settings-ui.test.mjs`：真实宿主保存、revision 冲突、原生 Switch 卡片和带点预设 id 的精确嵌套路径。
- `test/publication-boundary.test.mjs`：通用层不依赖内置产品规则，发现控制器不回引 consumer/integration。
- 原有权限、安全、PTC 投影、下一步激活、作用域族、结果生命周期、发布闭包与包内容测试继续作为回归门禁。
