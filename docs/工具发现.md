# 按需高级工具

English: [Advanced tools on demand](discovery.md).

`dsh-ops/discovery` 在每个符合条件的 Native 作用域中发布 `ops_discover_tools`。可描述所需能力（`metadata revision hash`），或指定完整公开名称（`select:ops_stat`）。发现仅选择工具，不执行文件操作。成功选择在当前工具轮次中保持待激活状态；所属会话提交 `step/end` 后，为紧接着的供应商请求发布。固定版本宿主先组装提示再触发 `agent/pre-step`，因此组装时等待本插件发布队列完成，并通过公开提示服务重新组装过期快照。提交边界前的诊断组装不会激活排队名称。注册只属于调用者；父、子和同级作用域都需独立发现。

七行 bundle 默认启用该组件，并保留已有带名称行覆盖。其配置如下：

```yaml
- name: dsh-ops/discovery
  config:
    enabled: true
    maxResults: 3
    allowedTools: [inspect_local_file, result, glob, grep, replace, write_file, edit_file, diff, stat, copy, move, remove, read_table, read_docx, read_pdf]
    alwaysLoaded: []
```

| 设置 | 默认 | 契约 |
| --- | --- | --- |
| `enabled` | `true` | 发布发现入口。设为 `false` 仍保留 `alwaysLoaded` 工具；禁用整个 Loader 行会卸载该行拥有的全部工具。 |
| `maxResults` | `3` | 每次选择上限，整数 1-5。调用参数 `max_results` 也校验为 1-5，并受本设置限制。 |
| `allowedTools` | 上述全部已实现高级能力 | 使用原始能力名称的允许池。不支持的格式会被拒绝，不会假装可用。 |
| `alwaysLoaded` | `[]` | 允许池中跳过发现流程的选择，从首个符合条件的步骤开始可用。 |
| `binaryPath` / `required` | 自动 / `false` | 与原生文件工具相同的 worker 选择及激活失败行为。 |
| `denyCredentialReads` | `true` | 保留原生文件凭据保护。 |

配置数组会复制并去重；未知配置键在错误中点名。搜索按经评审元数据确定性匹配关键词，同分时使用固定顺序，不调用模型。`query` 必须非空且不超过 512 个字符；额外操作参数会被拒绝。已实现的 read_table、read_docx、read_pdf 可按需发现，分别受[原生内核](原生内核.md)中的 CSV/TSV、DOCX 与受限 PDF 契约约束；不将二进制 DOC、OCR 或未支持 PDF 编码宣称为可用。

每个激活的文件工具保留自身路径基准、参数 schema、Native 渲染、worker 权限检查和修订值/CAS 契约。只读作用域不能激活写操作。沙箱模式变更会清空该会话待激活项、取消其执行中的调用并重新计算注册；其它会话保留选择。销毁 agent 或卸载组件会移除注册，缓存的旧定义也失效。纯 PTC 作用域不发布此 Native 发现工具面；SDK 由 PTC 适配器管理。

只使用本插件自己的作用域 `ctx.tools.register`、`restrict`、提示词段落和生命周期监听；不替换宿主方法或共享工具注册表。发布前比较目标工具名称，避免与 PTC 生命周期监听器互相触发重复注册。

## 测量边界

确定性的入口测量固定 `js-tiktoken@1.0.21` 和 `cl100k_base`，编码固定宿主 `ToolSchema` 字段（`name`、`description`、`parameters`）的紧凑 JSON。发现入口为 **94 tokens / 410 UTF-8 字节**。这是可复现的 schema 测量，不是供应商账单；不含消息封装、提示词指引和其它 OPS 组件。分词器是测试依赖，发布于 2025-08-09；锁定的 `base64-js` 也仅供测试使用。

默认文件/发现工具面为 `ops_read_files` 加 `ops_discover_tools`，**242 tokens / 1101 字节**。完整 Windows Bash/jobs 契约按供应商实际顺序为 **678 tokens / 3313 字节**（改名前快照为 660/3219，更早的目录顺序口径为 661 tokens）。已明确批准 BM-03 的 ≤400 token 门禁仅作用于文件/发现 schema；Bash 保持启动常驻，其成本及完整总数继续单列。高级读取、搜索、修改、文档与结果分页按需发现；路由只列出已发布工具。数值边界、默认值、路径基准与权限契约保持不变；始终加载项会扩大初始面。见[基准证据](基准门禁.md)。

BM-04 已通过真实 AgentLoop 验证已实现 PDF 读取器：初始 schema 不可见，当前轮保持等待，所属供应商下一请求可见，兄弟 agent 不可见，并成功读取 fixture 文本。这只验证已支持 PDF 子集，不代表通用 PDF/OCR 覆盖。

内置设置可持久化严格校验的数组；可选浏览器多选使用固定宿主客户端 API，需要[配置参考](配置参考.md)中的显式离线承载行迁移，默认旧文件行不启用这些页面。

重叠的发现行由最近作用域拥有；同一作用域最后挂载的行生效，卸载后恢复前一行。文件行可在发现组件之前或之后挂载。仅让出或屏蔽确切属于 OPS 的 Native 注册，外部注册保持可见。PTC 的 Native 投影保留确切来源，发现后的激活项不能被其它 agent 继承。Native `result` 仅含 page/release，可在只读模式发现；worker 仍会拒绝不允许的 release。常驻 `read_files` 和按需 `edit_file` 保留原有逐文件完整性和 CAS 契约。

BM-03 现在对已批准的文件/发现小计执行门禁，同时单列 Bash 及完整默认 Native 总数。仍须核验确切默认工具清单，包括可用的 Bash（Windows 固定载荷或宿主 bash）与宿主 jobs 契约；缺少工具应阻塞测量，不能换取更小分数。范围批准不改变默认值、参数或权限边界。
