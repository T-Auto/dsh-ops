# 会话输出溢写

English: [Session output recovery](session-spill.md)

本 #872 内部切片把持久会话输出接入新鲜任务已使用的同一个原生溢写存储和保留账本。
它不发布会话工具、不改变默认执行器，也不将现有 Windows 固定运行时认定为支持持久异步命令。

## 所有权与完成条件

常驻内核只创建一个 `SpillStore`，在 `READY` 前将其克隆交给任务与 Shell 管理器，
随后在 `shell-v1` 之外公布 `shell-spill-v1`。配置存储不执行文件系统 I/O；第一次输出
溢出由拥有该捕获流的读取线程延迟创建私有目录。创建失败时保留有界内存输出并报告
`spillError`，不会阻止内核启动或文件工具运行。

会话 stdout、stderr 仍分别保留 128 KiB 前缀。超过此边界才创建完整原始文件，包含此前
已在内存捕获的字节，每个流上限为 64 MiB。控制回执、协议前缀和原进程诊断不进入文件。
恰好达到内存上限时不创建文件；超过文件上限，或写入、封存失败时，撤回完整文件路径，
同时继续有界捕获。私有来源、禁止跟随重解析点、I/O 取消所有权及不可撤销的污染语义见
[私有通道溢写](私有Shell通道共享溢写.md)与[原生原始输出溢写](原生原始输出溢写基础.md)。

每条关联的 `shell.output` 回执可带 `spillPath`、`spillOrigin: "ops-native-v1"`、
`spillPid`、`spillSealed`，以及独立的退化说明 `spillError`。宿主要求已协商溢写能力、
来源字段齐全，并且 PID 必须匹配实际常驻握手。终态收集等待两个流均完成后才释放原生
记录。终态路径未封存，或多次终态读取间元数据变化，都会判为协议错误。原始捕获错误
保留已有字节，但不会虚构 EOF 或恢复路径。

只有清理已确认、已封存且自身无错误的捕获流才进入现有账本，归属于准确的调用 Session。
普通命令失败或取消仍可能留下完整捕获并封存的流；原始捕获错误或清理未知不能如此记录。
没有第二份账本或宿主溢写器。释放原生记录后，封存文件仍由现有有界保留机制管理。
恢复读取沿用现有绝对路径文件权限，写入权限不变。

## 验证与启用边界

实际公共宿主探针命令为：

```powershell
node bench/probes/probe-872-session-spill.mjs <worker.exe> <candidate-niu.exe> <stock-payload-niu.exe> <report.json>
```

九项检查覆盖：恰好达到内存上限；三种沙箱模式下完整二进制 stdout/stderr 恢复及工作目录、
导出变量、函数、选项保留；与新鲜任务共享同一存储；账本重载及准确 Session 归属；
文件读取恢复与写入拒绝；64 MiB 上限；保留清理；存在未封存流时内核死亡。
本地回移修复候选还执行外部后台命令及 `wait`，九项全部通过，清理已确认且无存活进程。

CI 以固定运行时及 `--stock-foreground` 验证同一路径中的前台外部命令。
这不证明现有运行时的异步输出完整性。公共会话启用仍须分别要求 `shell-v1`、
`shell-spill-v1` 和已验证的运行时。内部有界 `shell-v1` 测试夹具保持兼容。
POSIX Shell 所有权仍不支持；不引入进程组降级或静默改变清理范围。
